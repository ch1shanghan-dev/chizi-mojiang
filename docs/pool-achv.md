# 池子成就 · 设计方案（v1 · 2026-10-19）

> 作者需求原文：「能不能增加一个池子成就，跟生涯大厅/讨伐录同级，里面的内容是操控武将在斗地主/身份/对决模式里打出来的一些操作，可以记录成成就」「从 UI 交互到内容选择，都很重要」。

---

## 0. 一句话定位

**生涯成就回答「你积累了多少」，池子成就回答「你打出过什么」。**

现有 434 条生涯成就（`core/csh_achv.js`）几乎全是「同一个字段的阈值阶梯」——官阶 55 条、功勋 37 条、资产 40 条、场次/胜场/败场/击杀 70 条……本质是「数字再高一点」。玩家的实际游玩体验（一手漂亮的连招、残血翻盘、春天、一回合打穿）**完全没有被记录**。

池子成就补的正是这一层：**操作型 / 事件型**成就，判定源是局内事件流，不是快照数字。

---

## 1. 边界（先定死，避免又长成数值阶梯）

| 维度 | 规则 |
|---|---|
| 统计模式 | 身份 / 斗地主 / 对决（作者指定）。国战、BOSS 挑战、小游戏**不统计** |
| 联机 | **一律不统计**（`lib.config.connectMode` 直接 return）。理由：对手操作不可控、无法复核、且会给联机端增加每事件开销 |
| 旁观 / 调试局 | 不统计（`_status.importingExtension`、观战标记、`lib.config.dev` 调试局排除） |
| 单局判定上限 | 5000 次，超出熔断并打一条 `[池子成就][熔断]` 日志（防病态规则拖垮一局） |
| 形态 | 只做「事件达成」，**禁止**再做「累计 N 次就用同一件事堆 10 档」——阶梯最多 3 档（初/中/极），且必须换名字换角度 |

## 2. 数据模型

### 2.1 规则表（静态，随代码发布）

```js
{
  id:    "op_one_slash_kill",          // 全局唯一，也是存档键
  name:  "一刀两断",
  cat:   "操作",                        // 操作 | 连击 | 逆境 | 模式 | 武将
  rare:  2,                            // 1 普通 / 2 稀有 / 3 史诗
  modes: ["identity", "doudizhu", "duel"],   // 空 = 全部三个模式
  desc:  "单次造成 4 点或以上伤害",       // 「条件」，给玩家看
  hint:  "高伤害武将 + 铁索连环一类叠加",  // 可选，给方向（不剧透具体打法）
  on:    ["damage"],                   // 只在哪些事件上判定（用于建索引）
  once:  true,                         // 单局内最多触发一次
  test:  function (c, a) { return c.damage >= 4; },
}
```

`test(c, a)` 是**纯函数**：`c` = 本次事件上下文，`a` = 本局聚合器快照。不做副作用、不读 DOM、不读 `game` 全局——保证可被探针直接喂假事件跑。

### 2.2 进度存档（动态）

```js
// localStorage: csh_pool_achv
{
  v: 1,
  got:  { "op_one_slash_kill": { t: 1730000000000, m: "doudizhu", n: 3 } },  // n = 累计达成次数
  seen: { "op_one_slash_kill": 1 },   // 已读（清红点用）
}
```

只存 id + 时间 + 模式 + 次数，**不存明细**——60 条全解锁也就几 KB。

## 3. 采集层（唯一钩子）

项目红线是「禁万能 Hook」，所以这里不是「监听一切事件」，而是**一个隐藏全局技 + 一张固定的事件白名单**：

```
game.addGlobalSkill({ id: "csh_achv_tap", ... })
```

| 事件 | 来源 | 采集到的东西 |
|---|---|---|
| `gameStart` | 全局技 `global:"gameStart"` | 重置聚合器；记录模式、己方武将、人数 |
| `useCard` | `player:"useCard"` | 牌名、目标数、是否连招、当前手牌数 |
| `useSkill` | `player:"useSkill"` | 技能 id、是否觉醒/限定 |
| `damage` | `player:"damageBegin4"` 后取实际值 | 来源、目标、点数、属性、是否致死 |
| `die` | `global:"dieAfter"` | 死者、是否敌方、是否己方 |
| `judge` | `player:"judge"` | 判定牌、结果 |
| `gameOver` | `global:"gameOver"` | 胜负、回合数、存活人数 |
| `hpChange` | `player:"changeHp"` | 体力变化（用于残血判定） |

**纪律**：
- 全部 `silent: true`、无动画、无提示（不干扰牌局）
- 每个回调只做 O(1) 累加 → 进 `a`；规则判定只在 `on` 命中时跑
- 任何一步抛错都 `catch` 并只打一条日志，**绝不让成就系统影响牌局**

### 3.1 聚合器 `a`（本局累加量）

```js
a = {
  mode, myChars: ["xxx"], turns: 0,
  dmgMax: 0,          // 单次最高伤害
  dmgTurn: 0,         // 本回合累计伤害（回合切换时归零，并记 dmgTurnMax）
  dmgTurnMax: 0,
  cardsTurn: 0, cardsTurnMax: 0,
  kills: 0, dodgeStreak: 0, dodgeStreakMax: 0,
  useSkillChain: 0,   // 连续回合都有发动技能
  hpMin: 99, hpNow: 0,
  noDamageTurns: 0,   // 连续未受伤回合
  played: {},         // 本局出过的牌名集合（春天/全牌堆类判定）
  judges: { total: 0, hit: 0 },
}
```

## 4. 判定与性能

1. 建表时按 `on` 建索引：`INDEX["damage"] = [规则…]`，事件到来只跑相关规则。
2. `once` 的规则触发后，从本局活跃集合里移除（数组尾部交换删除，O(1)）。
3. 每条规则 `test` 内部必须 O(1)——禁止遍历全场武将。
4. 一局 40 条规则 × 数百事件 ≈ 千级函数调用，性能可忽略（对比 `simulate_world` 的量级）。
5. 熔断：`judgeCount++ > 5000` 时停判并记日志。

## 6. UI 设计（作者最在意的部分）

### 6.1 入口卡（池子世界内）

第四张手写卡，与「生涯大厅」「讨伐录」「天下榜」同级同规格（`button.csh-dbg-gamebtn.gb-achv`）：

```
┌─────────────────────────────┐
│ 🏅 池子成就                  │  ← gb-name
│ 已解锁 12 / 60 · 稀有 3      │  ← gb-mid（专属色，建议青金 #c9a84c）
│ 记录你在对局里打出的操作      │  ← gb-desc
└─────────────────────────────┘
```

- 有新解锁未读 → 右上角红点（复用 `gb-unread` 的实现）
- 色系：金（与生涯的浅蓝、讨伐录的朱砂、天下榜的青蓝区分）

### 6.2 页面 `games/achv.html`

```
┌──────────────────────────────────────────────┐
│ ← 返回      池子成就        已解锁 12/60  ⭕45% │
│                                              │
│ [全部] [操作] [连击] [逆境] [模式] [武将]      │ ← 筛选 chips，单行可横滚
│                                              │
│ ┌──┬──────────────────┬────────────┬───────┐ │
│ │▍ │一刀两断            │单次造成 4 伤害│ 已解锁 │ │
│ │▍ │斗地主 · 身份 · 对决 │              │ 2 次  │ │
│ └──┴──────────────────┴────────────┴───────┘ │
│ ……                                           │
└──────────────────────────────────────────────┘
```

- 左侧 4px 稀有度色条：普通 `#8a8a8a` / 稀有 `#c9a84c` / 史诗 `#9b59d0`
- 行内三栏：图标+名字 / 条件 / 状态（已解锁 + 次数，或「未解锁」）
- 点击行 → 详情层：
  - 大图标 + 名字 + 稀有度
  - 「条件」全文 + 「提示」（若有）
  - 「你的记录」：首次达成时间、模式、累计次数
  - 奖励与「领取」按钮（未达成时按钮禁用并显示「未达成」）
- 空态：`还没有解锁任何成就 —— 去身份/斗地主/对决里打一局`（有行动指向，不是干巴巴一句"暂无数据"）
- 移动端：单列、卡片高度自适应、**不允许横向滚动**（规范 §21）
- 动画：解锁瞬间只在牌局结束的回执里 toast 一次，不在局中弹（不打断操作）

### 6.3 交互纪律

| 纪律 | 理由 |
|---|---|
| 局中**绝不弹窗**，只在 `gameOver` 后汇总提示 | 打断操作是这类系统最容易犯的错 |
| 一局最多 toast 一次（「本局解锁 3 项 · 点击查看」） | 否则一次爆发刷屏 |
| 已解锁的条目仍有"次数"，可反复达成 | 给老玩家持续反馈 |
| 未解锁条目不隐藏、不锁灰度 | 看得见目标才有动力 |
| 全部进度只读 localStorage，不进存档包 | 换机丢成就不影响对局数据 |

## 7. 内容清单（首批 40 条）

### 7.1 操作（12）

| 名字 | 条件 | 稀有 | 判定 |
|---|---|---|---|
| 一刀两断 | 单次造成 ≥4 点伤害 | 2 | `c.damage >= 4` |
| 雷霆一击 | 单次造成 ≥6 点伤害 | 3 | `c.damage >= 6` |
| 从容不迫 | 手牌为 0 时仍赢了这一局 | 2 | gameOver 时 `hp>0 && hand==0` |
| 一气呵成 | 单回合使用 ≥5 张牌 | 2 | `a.cardsTurnMax >= 5` |
| 不动如山 | 整局未受到任何伤害并获胜 | 3 | `a.hpMin == 满血 && win` |
| 判若神明 | 单局判定命中 ≥3 次 | 1 | `a.judges.hit >= 3` |
| 万箭齐发 | 一张牌指定 ≥3 个目标 | 1 | `c.targets >= 3` |
| 空手夺刃 | 无手牌时闪避成功 | 1 | `c.cardName=="闪" && hand==0` |
| 铁壁 | 单局闪避 ≥3 次 | 1 | `a.dodgeStreakMax >= 3` |
| 逆流而上 | 单局从 1 血回到满血 | 2 | `a.hpMin==1 && hp==max` |
| 斩草除根 | 一回合内击破 2 名角色 | 3 | `a.killsTurn >= 2` |
| 长驱直入 | 单局回合数 ≥20 仍获胜 | 1 | `turns>=20 && win` |

### 7.2 连击（8）

| 名字 | 条件 | 稀有 |

| 连环计 | 连续 3 回合都发动技能 | 1 |
| 势如破竹 | 连续 4 回合造成伤害 | 2 |

### 7.5 武将 / 奇观（4）

| 名字 | 条件 | 稀有 |
|---|---|---|
| 本命 | 用同一名武将累计获胜 20 次 | 2 |
| 百将 | 用 50 名不同武将各胜 1 次 | 3 |

## 9. 门禁 E52（实现时必须一起提交）

1. 规则表：`id` 全局唯一 · `cat` 在白名单 · `modes` 非空且都在三模式内 · `desc` 非空 · `rare` ∈ {1,2,3}
2. 事件白名单：`on` 只能取 §3 表里的 8 个事件
3. 联机守卫在位：源码必须能在 tracker 入口找到 `connectMode` 早退
4. 存档键 `csh_pool_achv` 已登记 `csh_migrate`（E41 会连带检查）
5. 页面在 `csh_registry` 与 E32 的 CARDS 里登记（与 rank/bossbook 同规格）
6. **可行性自检**：探针喂假事件流，断言「该触发的触发、不该触发的不动、重复事件不重复计数」

## 10. 施工顺序（7 步，每步独立可验）

1. **采集器 + 聚合器**（无 UI）→ 探针喂假对局，打印聚合量
2. **规则表 40 条 + 判定器** → 探针跑「单次伤害 4 点」等 12 个正例 + 6 个反例
3. **存档 + 迁移 + 门禁键表** → 重启后进度还在
4. **入口卡**（池子世界第四张卡 + 红点）
5. **页面骨架**（列表 + 筛选 + 空态）
6. **详情 / 领奖 / 未读**（复用生涯成就的领奖复核桥）
7. **内容扩到 60 + 实机三模式 + 联机确认不统计 + 门禁 E52**

---

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 与别的扩展抢事件钩子 | 单点全局技、`silent`、`catch` 包死；不修改任何引擎对象 |
| 判定误报（同一事件多次触发） | 事件去重：同一 `card`/`skill` 实例 id 只计一次 |
| 存档被玩家手改 | 只是本地成就，不做防作弊；奖励核销仍在宿主侧 |
| 模式判定漂移（引擎改 mode 名） | `modes` 用白名单 + 启动时打一条诊断，未知 mode 直接不统计 |
| 成就把玩家推向"刷"而不是"玩" | 阶梯最多 3 档、条件必须"一次对局内可完成" |
