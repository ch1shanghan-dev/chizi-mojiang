## 研究时作出的区分

1. **本机运行代码优先解释本机行为**。上游 GitHub 的 apps/core、TS 源码与打包 JS 路径不同；记录仓库、commit、文件与函数。技术依据采用官方源码/文档和目标扩展维护者仓库。
2. **三种坐标系不同**：宿主 body 的 scale/zoom、挂在 documentElement 的浮层、iframe 内页面。先量矩形与真实遮挡，再改 CSS；不用更大的 z-index 或缩小文字代替布局处理。
3. **界面与持久化状态不同**：移除 DOM 不等于清理监听器/定时器，函数返回不等于异步写盘成功，可见不等于实际接收点击。
4. **世界拟人化与对局 AI 决策不同**：这里维护事件、关系、台词与表现，不读隐藏手牌、不增加战斗决策 Hook，不为此引入 LLM 服务。
5. **已有门禁通过不等于无缺陷**：用行为断言覆盖本次缺口，不删断言或把已复现缺陷改成 PASS。

## 项目契约

- registry 是游戏目录和结算参数真源，wallet 是经济账本；migrate 按实际后端导出/清洗/回写。
- shell-settle* 成功 ACK 后才标记完成；失败释放认领、重试只兑现一次。考虑迟到 ACK 和打开新 iframe。
- UI 复用 csh_uikit、theme/层级/字号与壳安全区，保留各模块联机守卫，不默认扩大联机能力。
- 模态框重入须结束或排队旧实例；旧回调不能被新弹窗确认。取消、销毁和连点都只能完成一次。
- 胜率分清角色出场、玩家对局、身份阵营和模式；双将不等于两局。“我的角色”统计不能藏在身份专属分支。
- AI 记忆先读既有事件再写当前事件，区分 actor→target。延迟表现执行前复核会话、对象和开关，避免旧局继续发言。
- 配置写入核对宿主完成/失败通道，不把 try/catch 包住 game.saveConfig 当成异步事务成功，也不以 await undefined 宣称修复。
- 当前只发静态基础版，保留零 import 双载脚本与引擎 ESM 边界，不按历史动皮提案顺手恢复分档。
- 保持扩展根目录整洁：报告/方案/清单/截图放 `docs/`（本轮统一 `docs/audit/`），脚本放 `tools/`，临时产物与备份放扩展之外；不按原方案旧条款在根目录新增报告。
