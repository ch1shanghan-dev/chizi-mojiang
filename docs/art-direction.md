## 四、A1 · 字体三档与字号标尺（2026-10-07 落地 · 样板页 career.html）

### 4.1 三档字体（按**语义**分档，不按大小）

| 档 | token | 字体栈（回退链） | 用在哪 |
| --- | --- | --- | --- |
| ① 标题宋 | `--ff-title` | `"Noto Serif SC","Source Han Serif SC","Songti SC","STSong","SimSun",serif` | 页签菜单 / 区块标题 / 官阶名 / 大数字 |
| ② 正文黑 | `--ff-body` | `"Noto Sans SC","PingFang SC","Microsoft YaHei",system-ui,sans-serif` | 正文 / 说明 / 按钮 / 普通标签 |
| ③ 数字牌 | `--ff-num` | `ui-monospace,"Cascadia Mono",Consolas,"SF Mono",Menlo,monospace` | 余额 / 榜值 / 进度 / 计数 / 编号 |

**为什么是这三档**：中文界面里「宋 + 黑」的对比本身就是高级感来源 —— 标题有骨、正文稳当；
数字单独一档是因为界面里所有数字都要**竖着对齐**（等宽 + `font-variant-numeric:tabular-nums`），
对齐这件事由字体解决，而不是逐处 `margin` 补。

### 4.2 字号标尺（单一基数派生 · 移动端优先）

```css
--fs-base:12.5px;                        /* 基数：按手机横屏（915×412）定档 */
--fs-tiny:calc(var(--fs-base) * .8);     /* 10px   角标：菜单编号、徽章刻度 */
--fs-cap:calc(var(--fs-base) * .92);     /* 11.5px 辅助：字段名、脚注、进度 */
--fs-body:var(--fs-base);                /* 12.5px 正文：说明、按钮、列表行 */
--fs-lead:calc(var(--fs-base) * 1.2);    /* 15px   导语：卡片主标题 */
--fs-menu:calc(var(--fs-base) * 1.44);   /* 18px   菜单：页签 */
--fs-title:calc(var(--fs-base) * 2.08);  /* 26px   标题：官阶名、面板标题 */
--fs-display:calc(var(--fs-base) * 2.32);/* 29px   数字牌：全页唯一主角 */
```

三条纪律：
1. **只由基数派生**——「改一个数字，全页按比例呼吸」；禁止页面里出现标尺外的裸字号（含 10.5px / 22px / 20px 这类历史值）。
2. **移动端优先**——基数按手机横屏定档，桌面用同一套值（不设第二套断点数字）。
   在手机上成立的密度，在桌面上必然成立；反过来不成立。
3. `rem`/多个断点数值表一律不用——它们是同一事实的多份副本。

### 4.3 断点判定：手机横屏比桌面断点**宽**

实测事故级坑（本轮抓到）：手机横屏是 **915×412** —— 比 career.html 的 `min-width:900px` 桌面断点还宽。
按宽度写移动端规则会被手机**全部绕过**（走进桌面分支：侧栏 200px、内距偏松），而它只有 412px 高。
⇒ **紧凑断点一律用 `max-height`**（`@media (max-height:640px),(max-width:899px)`），与 `csh_layout.css` 的 L-SHORT/L-TINY 同口径。

### 4.4 移动端信息密度口径（作者定则 2026-10-07）

> 「尽量让所有主要信息都能在手机屏幕里显示，除非必须情况才滑动。」

压缩的**优先顺序**（不藏信息、不缩字号）：
① 侧栏收窄（200→168px，把宽度还给内容）→ ② 卡片内距 / 块间距收紧（省留白）→
③ 网格按内容宽度自适应列数（`auto-fill` + `minmax`）→ ④ 最后才考虑内部滚动区。
**禁止**：靠隐藏信息达成"一屏"（与 §二 L-SHORT「只压字号与间距，不藏信息」同一条红线）。

### 4.5 移动端信息架构口径（A1.5 · 2026-10-07 · 作者定则）

> 「尽量让所有主要信息都能在手机屏幕里显示，除非是必须情况才滑动。」

**手段只有三种，按顺序用，都不许删信息**：
① **改排布**（首选）—— 竖排改并排。生涯大厅总览：`横幅（官阶焦点卡）+ 左窄右宽两列`；
② **改密度** —— 侧栏 200→168、卡片内距 12→8、行高 56→42、徽章 76→44（都是留白与装饰，不是内容）；
③ **两档文案** —— 同一份真值、两种写法：窄屏「23/50 · 还需 0 · 门票 10% · 签到 +500 · 带入 20,000」，
   桌面「第 23 阶 / 共 50 阶 · 距下一阶还需 0 功勋 · 门票折扣 10% · 签到加成 +500 CBY · 带入上限 20,000」。
   **只省略可由上下文理解的限定词，数字一个不少**；`aria-label` 存完整文本。

**两档文案的实现（一次踩坑换来的）**：用 `.two-tier` 包两个 span（`[data-full]` / `[data-compact]`），
CSS 按尺寸只显示一个。**不要**用 `data-* + ::before{content:attr()}` —— `attr()` 只输出纯文本，
文案里带 `<b>` 强调时会把标签当字面字符打出来。

**Flex 与 Grid 的分工（实测结论）**：
- 窄屏总览用 **flex**（`flex-wrap` 分行 + `order` 排序 + 两列各自成栈）——列内向上补齐，没有死白；
- 宽屏总览用 **grid**（`display:contents` 摊平两个列容器 + 逐块 `grid-column: 起/止` 双值定位）。
  两个坑写在这里：① `display:contents` 下 `:nth-of-type` 的计数与直觉不符（实测「资产」被算成第 1 个、
  错拿 row3，两块叠在同一格）——**一律用 `:nth-child`**；② 只写 `grid-column:1` 时若与别的显式项冲突，
  grid 会把该项**整行撑满**（实测「资产」被拉到全宽）——**一律写起止双值**。

**验收口径**：改完必须报三档尺寸的「内容高 / 可视高」（桌面 1000×756 / 手机横屏 915×412 / 竖屏 412×915）。

### 4.6 材质光影（A2 · 2026-10-07 落地）

**三件套**（选样页 `tools/material_ab.html`，每个工件给 2~4 个候选并排比材质）：

| 件 | 做什么 | 写法 | 用在哪 |
| --- | --- | --- | --- |
| ① 发丝金线 | 一根「被光照到的金丝」：上缘亮 → 中段金 → 下缘收 | 双背景技法：`linear-gradient(底) padding-box, 渐变 border-box` + `border:1px solid transparent` | 所有卡片 / 结局面板 |
| ② 金晕微光 | 顶缘金高光 + 底部压暗 = 卡片浮起 | `inset 0 1px 0 rgba(金,.20), inset 0 -18px 26px -20px rgba(0,0,0,.9)` | 数据卡 / 「你」行 / 结局面板 |
| ③ 光影金 | 垂直渐变 + 顶缘内高光（金属感来自光在同一方向） | `linear-gradient(180deg, 金, 暗金)` + `inset 0 1px 0 rgba(255,255,255,.3)` | 主按钮 / 重点卡（游戏页按钮早就是这个做法） |

**三条纪律**：
1. **只画不排** —— 材质一律走 `border`/`background`/`box-shadow`，**绝不碰 `padding`/`margin`/尺寸**。
   材质永远不该改变布局（这也是"一屏"验收不被材质破坏的保证）。
2. **单一真源** —— 三档金与两条渐变集中声明（生涯大厅在页内 `:root`，游戏页在 `csh_layout.css`），
   消费方只写 `var()`，不写第二份色值。
3. **明暗有方向** —— 金属感 = 光从上往下。任何渐变都从上缘亮到下缘暗；反着来会变成"塑料"。

**分隔线**（本轮新增）：通栏 1px 实线 → **中间实、两端收**的渐隐金线，用 `background-image` 单像素条实现：
```css
background-image: linear-gradient(90deg, transparent, rgba(金,.34) 22%, rgba(金,.34) 78%, transparent);
background-size: 100% 1px; background-position: top left; background-repeat: no-repeat;
```
通栏实线太像表格边框；渐隐线才像"手绘的一道界"。

**踩坑记录（禁用态）**：主按钮的墨字是**压金色实底**才成立的；一旦禁用退回素底，墨字就成了深底深字。
⇒ 禁用态必须把前景翻回浅色、压掉金底与描边（`.btn:disabled{background:rgba(255,255,255,.05);color:var(--text-dim)}`），
状态要一眼可辨。这条与 A1 的"两档文案"同源：**同一元素在不同状态下可以换材质，但不能换掉可读性**。

### 5.2 武将立绘高清化（作者 2026-10-07 指示 · 待素材）

**目标**：`image/` 下 131 张立绘换成高清版。**状态：待作者提供素材，暂不实施。**
施工要点（照 README §7 M2 的"曝光尺寸分配"决策）：
1. **按曝光尺寸分配规格**：局内头像显示尺寸小 ⇒ 中等规格；资料卡 / 演出等全屏场景才给最高规格

3. 体积纪律：单张 **≤1.5MB**，格式优先 WebP（已有 webp 先例）；
   可复用做过的资源优化手法（GIF→WebP / PNG oxipng）。
4. **不改名、不删旧图**（红线）；新图先并排入库、实测通过再切引用。
