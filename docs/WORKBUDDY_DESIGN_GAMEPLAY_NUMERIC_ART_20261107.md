## 2. 妖灵 50 名特色增益（玩法 + 数值）

### 2.1 先划红线

- **不新增存档键**。解锁状态从 `csh_affection` 现有好感档位读，每局触发次数放助战运行态。
- **不产生 CBY、不改奖励、不碰成就凭据**。经济回报已有四档特权 + 回礼，再加一份就是双份。
- **不改胜负判定、不读隐藏信息、不碰牌堆**。
- **单一档位解锁**：好感度到 **B（亲近）** 解锁该妖灵的特色增益，**A/S 不升级效果**。
  50 只 × 5 档 = 250 组强度组合，没法平衡，也没必要。
- 所有效果 `magnitude=1`、`perGame=1`。每局最多触发一次，不叠、不跨局累积。

**实施期语义修正（2026-11-07，D4）**：`perGame=1` 对六类模板不是同一种含义，原表述会让
T3/T4 接上引擎就出错。引擎的 `maxHandcard` / `globalFrom` mod **每帧都会查询**，
若每次查询都走一次性 `consume`，第二次就会被判 exhausted。定案分两类：

| 类型 | 模板 | 运行态入口 | 语义 |
| --- | --- | --- | --- |
| 一次性触发 | `T1` 减伤 / `T2` 摸牌 / `T5` 响应 / `T6` 回复 | `consume()` | 首次事件触发一次，之后再不触发 |
| 持续型常驻 | `T3` 手牌上限 / `T4` 距离 | `activate()` + `isActive()` | 本局**激活一次**后常驻到助战结束；重复查询不再消耗次数 |

两类共用同一份 `perGame` 计数，**天然互斥**（先 consume 再 activate 或反过来都会被拒），
不会出现「一只妖灵既触发一次性又常驻」。详见 `docs/audit/WORKBUDDY_S4_SEMANTICS_20261107.md`。

### 2.2 定案：6 个模板，镜像敌方技能语义

增益不是给 50 只凭空编设定，而是把**它作为敌人时的技能方向反转**成助战效果。
玩家看到「伊芙 · 魂矢」在讨伐里是魔王杀伤 +1，助战时就该是护主减伤 —— 同一套叙事，两个位置。

| 模板 | 效果 | 敌方语义 |
| --- | --- | --- |
| `T1_guard_damage` | 本局首次受到伤害时，此伤害 -1 | 增伤 / 杀伤 / 出杀 |
| `T2_draw_once` | 本局首次出牌命中后，摸 1 张牌 | 摸牌 / 夺牌 / 追加 |
| `T3_hand_cap` | 本局手牌上限 +1 | 手牌上限 / 弃牌 / 挑拨 |
| `T4_distance` | 本局与其他角色的距离 -1 | 距离 / 潜入 / 瞬步 / 隐身 |
| `T5_response_once` | 本局首次需要响应时，可视为已响应 1 次 | 拆闪 / 响应 / 判定 |
| `T6_recover_once` | 本局首次濒死时，回复 1 点体力 | 回复 / 自愈 / 濒死 |

## 3. 德州：真实补码 / 桌级退隐联动 / 第四款 AI（玩法 + 数值）

### 3.1 真实补码重上桌 —— 规则定案

现状零实现，所以先把不变量写死，再谈交互。

- **时机**：只在一手结算完成、下一手发牌前提供。手牌进行中、加注锁定中、结算未落盘时**禁止补码**。
- **额度**：`topUp = min( ceilTo10pct(minBuyIn - tableChips), walletBalance )`，
  `ceilTo10pct` 向上取整到该档带入的 10%（200 档 = 20 的整数倍）。低于 10% 不提供。
- **次数**：每桌上限 **2 次**。补码后不重置本桌前注/场供参数、不重算已结算手数、不改已入座者的 stake/skill。
- **扣款**：走 `csh_wallet` 与开局带入**同一条**扣款路径，读回确认后才增加桌面筹码；
  失败时桌面筹码不变、可重试，绝不出现「扣了钱没上桌」或「上桌了没扣钱」。
- **账本守恒不变量（必须做成反例断言）**：
  `钱包支出 = 桌面筹码 + 系统场供 + 已结算派彩`，补码只是资金从钱包移到桌面，
  **不产生也不销毁 CBY**。前注入池不是系统销毁，两列不能相加宣称经济回收
  （`TEXAS_EXPERIENCE_20261028.md:30` 已明确）。
- **随时可拒绝并离桌**；不自动补码、不自动开下一场、不替玩家消费
  （`MINIGAME_AI_AUDIO_REQUIREMENTS_20261028.md:7` 的定则）。

**实施状态（2026-11-07，D2 已落地）**：窗口确认存在（`showHandBanner()` 是玩家点「下一手」
才继续，不是自动开），所以补码插在结算横幅的按钮区，两种分支（含输光）都提供。
头号红线已核实并锁成反例：`endSession()` 用 `G.buyIn` 当本金基数，
`chips += N` 必须同时 `G.buyIn += N`，否则补码的钱被当成盈利发回钱包。
额度基准用「原始带入 = `G.buyIn - G.topUpTotal`」，不随补码累加漂移。
宿主 `shell-topup` 走同一条 `wallet.spend` + `pc()` 读回，独立校验次数与额度，
不信任子页面金额。

**D3 已补齐跨进程缺口**（`docs/audit/WORKBUDDY_D3_TOPUP_JOURNAL_20261107.md`）：
`spend` 的 `scheduleSave()` 异步写盘问题，用独立的本机未决凭据解决——
扣款**前**同步落盘 `prepared` 凭据，页面上桌后 `commit` 清除，启动发现未决凭据时
按 `balanceBefore` 判断扣款是否真的持久化，**幂等退款且钱包没扣款时绝不退款**（否则白送钱）。
凭据已登记进 `csh_migrate.js` 的 EXCLUDED，不随行囊迁移。
方案 §3.1 的两条「绝不出现」现在在跨进程层也成立；仅剩真机断电实测归作者 U5。

### 3.2 桌级 × 退隐联动 —— 只动席位来源，不动公平性

作者禁止「偷偷改变发牌」和「玩家难度选择」。所以联动**不能**改 AI 强度、stake、牌技或发牌。

**实施期纠偏（2026-11-07，已落地）**：方案初稿有两处与代码事实不符——

1. `core/csh_world.js` 的 `activeList()` 早就是 `!a.retired && fund >= AI_MIN_STAKE`，
   `seat()` 的候选池**无条件排除已退隐角色**。原表「0–49 全池 / 50–99 排除已退隐」
   不是待实现能力，照做等于没有改动。
2. 原文「退隐越多，跨桌重复出现同一角色的概率越低」因果是**反的**：
   退隐只会**缩小**候选池，反而提高重复率。

真正缺的是「同一角色不连续出现在相邻几桌」的**跨桌冷却**。按以下口径落地
（`core/csh_seat_cooldown.js`：纯函数 + 纯内存历史，不落盘、不写钱包、不改世界存档结构）：

| 当前退隐 | 冷却桌数 | 说明 |
| --- | --- | --- |
| 0–99 | 0 | 与既有行为完全一致，零回归 |
| 100–149 | 1 | 本桌排除上一桌出现过的角色 |
| 150+ | 2 | 本桌排除最近两桌出现过的角色 |

只过滤**候选池**；过滤后候选为空时降级回完整池，绝不空桌、绝不改变能否开局。
已入座者的 stake / skill / persona / 发牌一律不改。桌级 4 档保持不变，
唯一真值继续在 `csh_wallet.BUYIN_TIERS`，页面只读展示。
反例与验收见 `docs/audit/WORKBUDDY_AUDIT_AND_SEAT_COOLDOWN_20261107.md`（门禁 E95T，42/0）。

### 3.3 第四款 AI 牌风 —— 参数定案

现有 `tag / loose / bluff` 三种（`csh_texas_ai.js:4-7`）。补 `trapper`（陷阱型：收紧开池、放慢强牌、极少诈唬）：

| persona | edge | valueOpen | open | bluff | size |
| --- | ---: | ---: | ---: | ---: | ---: |
| tag（现有） | .055 | .59 | .57 | .045 | .66 |
| loose（现有） | -.015 | .65 | .40 | .025 | .45 |
| bluff（现有） | .025 | .56 | .47 | .130 | .75 |
| **trapper（新增）** | **.075** | **.68** | **.62**（实施期纠偏，初稿 .34） | **.020** | **.52** |

**实施期纠偏（2026-11-07，D1）**：`style.open` 在 `core/csh_texas_ai.js:decide()` 里是
「翻前后位偷池 / 便宜跟注」的 `strength` 门槛，**数值越高越紧**（tag .57 / bluff .47 / loose .40），
不是「开放程度」。初稿给 trapper 写 .34 会把它变成四款里最松的一款，与「收紧开池」自相矛盾；
按代码语义定案为 **.62**，比最紧的 tag 还高一档。参数表其余四项不变。

这是**世界角色的牌风**，不是玩家可选的难度档。快照仍只含自己的牌与公开事实，
隐藏牌/牌堆 getter 抛错的测试必须照常能决策。验收沿用既有口径：
VPIP/PFR 按发牌手数去重、诈唬不泄漏到台词、10000 手自对弈 0 停滞 / 0 非法行动 / 0 筹码守恒失败。

**实施期查出的真缺陷（方案阶段没看到）**：`games/texas/texas.html` 的 `PERSONA_MAP` 自
2026-09-29 起只写了 5 个世界牌风（aggro/tight/math/bluff/wild），而 `core/csh_world.js`
自 v6.3 起已有 **12 种**。其余 7 种（chaser/trapper/grinder/bull/maniac/reader/lucky）
全部落进 `pickPersona()` 随机三选一 —— 世界角色精心设计的牌风在德州桌上被丢掉。
D1 一并补齐到 12 个：既有 5 条为不改既有对局行为特意保留；新增 7 条按
`csh_world` 的 `raiseThreshold` / `bluffRate` 机械推导（高诈唬→bluff、高门槛→trapper、
低门槛→loose、其余→tag），规则与逐条依据写进页面注释并由门禁断言复算。
`mapPersona` 同时改用 `hasOwnProperty`，堵住 `toString` / `__proto__` 这类原型键返回
`Object.prototype.toString` 的旧行为。

| `vp-portrait` | 390×844 | 竖屏，纵向列表 |

**实施期纠偏（2026-11-07，E2）**：原写「统一 `--csh-vp-short:420px` 替代混用的 330/500」，
复核源码后不成立——330 是**极矮横屏 640×286 的额外收缩**，500 是**一般矮横屏
915×412 / 844×390 的常规收缩**，是两档有意分层；合并成 420 会让 640×286 拿不到
额外收缩，直接违反 §4.2「主操作与公共牌必须在首屏」。而且全仓实际有 **24 种**
`max-height/max-width` 断点值（不是 3 种），一次收敛要同时重画十几页并逐页比截图。

故本轮按事实落地为：① `core/csh_viewport.js` 作四档分类与令牌的**唯一真值**；
② `csh_layout.css :root` 写 `--csh-vp-tiny-h:330px` / `--csh-vp-short-h:500px` /
`--csh-vp-narrow-w:760px`（media query 不能用 `var()`，此组是文档与未来迁移的单一来源）；
③ 门禁把 24 种历史值固化为**基线白名单**，先锁住「不扩散」，**不改任何现有 @media 数值**
（零布局风险）；④ 逐值收敛仍是后续待办，须按 §4.4 逐页比 `docs/audit/ui/` 基线截图。
`art-direction.md` 4.3 的「手机横屏比桌面断点宽」继续有效：**不要**因为看到 `width>760`
就套桌面布局——桌面档必须同时满足 1365×768，已做成反例断言。
详见 `docs/audit/WORKBUDDY_E2_VIEWPORT_TOKENS_20261107.md`。
