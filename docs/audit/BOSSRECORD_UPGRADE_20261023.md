# 讨伐存档跨更新保全与观察器收尾修复 · 2026-10-23

这是实际安装目录的本地修复。保留其他未提交改动，版本仍为4.0.10，未提交、发布或更新桌面ZIP。武将AI暂停，其他人物立绘未动。

## 根因与交付

金鳞市已确认的同名ZIP更新问题也影响讨伐：宿主`game.importExtension`先执行`removeExtension(name,true)`，删除全部`extension_池子魔将*`配置。因此原有`bossKill`、`bossAsBoss`、`csh_bounty`三键都存在被删除的风险，存储键没有改名。此前恢复守卫仅防止恢复期间写入，不能防止更新删除配置。

现在钱包的`bossSaved`保存三个域的独立JSON副本。安装记录模块时先保全仍存在的旧配置；旧的同名localStorage记录也可读取并保全。正常写入先严格保存钱包副本，再向宿主原配置键提交兼容镜像；记录模块和导出优先读取保全副本。配置镜像同步抛错或异步没有落盘时，已确认副本仍可重启读取。空间不足导致副本写入失败时，拒绝本次记录及后续奖励。

启动正处于恢复锁时不创建副本。解锁后的第一次新写入会先保全其余旧域，不会只保存当前域、漏掉应战和悬赏。损坏的根对象、字段和不可读旧JSON不当作空档覆盖；返回的副本不能反写已保存对象。副本没有新增独立localStorage键，仍由现有钱包持久化。

行囊按原有`bossKill/bossAsBoss/bounty`域扁平化导出，界面不新增重复的内部域。单独导入讨伐/应战/悬赏时，钱包副本也纳入写入计划及原值恢复journal；单独导入钱包则保留没有指定的本机讨伐域。回滚和明确重置同步副本，重启不会用旧副本复活已经重置的数据。

`skills/boss.js`仅改非战斗记录观察器：挑战者击破、应战胜、应战负三个分支均在记录函数接受后才设置`_cshBossRecorded`。保存被拒绝不占完成标记；接受后与原生结束通道共用标记，只计一次。其他技能、AI、触发条件、战斗机制与数值均未修改，并做了源码范围核对。

修改文件：`core/csh_wallet.js`、`core/csh_bossrecord.js`、`core/csh_migrate.js`、`skills/boss.js`。新增验证脚本`tools/probe_bossrecord_upgrade.mjs`。

## 未解决的边界

保护生效需要本版在旧数据仍存在时成功保全一次。对已经被删除、且没有钱包副本/旧localStorage/行囊/其他备份的历史记录，不能从余额或猜测重建。本批没有声称找回作者真实丢失的数据。

副本写入确认只涵盖记录，**没有把记录与全部奖励合成一个经济事务**。普通`wallet.add`仍是延迟保存；记录与CBY、功勋、好感度和悬赏收费之间的崩溃窗口、限额实得与名义收益日志、可靠补偿仍需下一批处理。配置镜像没有新建自动后台重试任务，扩展内读侧及行囊使用副本；外部扩展若直接读取原配置键，镜像失败后可能暂时看到旧值。完整BOSS对局、安卓和其他扩展组合仍待验证。
