# B3 · 行囊跨版本兼容（新版本必须能正确运行、在线更新同理）

日期：2026-11-05。编制：WorkBuddy。触发：作者报告「行囊跨版本不匹配」，并明确**不修老版本，只保证以后的新版本与在线更新可靠**。

## 结论先行

- 当前行囊格式 **v3**，`meta.v > VERSION` 才拒绝，旧版本走清洗补缺；正常导入 `applyAll(..., false)` 对缺失键**保留本地值**，只有本机备份回滚才完整覆盖。
- 4.0.15 → 4.0.16 **没有改** `VERSION`、`KEY_DEFS` 或任何存档键结构（4.0.16 只改版本号与文档），所以在线更新后旧档可直接读取。
- 新增跨版本专项 **10/0**，把「旧行囊可导入、新键不被清空、未来版本明确拒绝、篡改拒绝」变成可复跑的承诺。

## 实测行为（不是推断）

| 场景 | 结果 |
| --- | --- |
| 当前 v3 行囊导出 → 回读 | 成功，`meta.v=3`，余额与导出时一致 |
| v3 行囊导入全新档 | 覆盖余额与官阶，`reloaded` 确认 |
| v1 行囊（仅 wallet+rank） | 接受；缺失域保留本地值 |
| v1 导入到已有新数据的档 | 钱包/官阶生效；`csh_ddz_name`、成就通知归档、目标追踪等**新键原样保留** |
| v2 行囊（含 winrate） | 接受 |
| 未来 v4 行囊 | 明确拒绝：「文件来自更新的版本…请升级扩展」 |
| 篡改内容 | 拒绝：「校验不符」 |
| 空/前缀错/坏 base64/坏 JSON | 分别给出明确错误，不崩 |
| 未知键 | 忽略，不写入本地 |
| 导入旧包后再导出 | 新版本本地键仍在，且不进入导出体（属本机数据） |

夹具：真实 `core/csh_migrate.js` + `core/csh_wallet.js`，隔离 localStorage；不接触玩家存档、不改项目文件。

## 为以后立的纪律（写进 AGENTS.md）

1. **新增存档键允许旧行囊缺失**：清洗器对 `null/undefined` 必须返回 `null` 跳过，而不是抛错拒绝整包。
2. **不得改变已有键的结构或语义**；必须改时升 `VERSION` 并提供迁移路径。
3. **`VERSION` 只升不降**；升版本前必须跑 `tools/probe_migrate_compat_20261105.mjs` 且 10/0。
4. **导入失败不半写入**：当前是整包拒绝、原子提交（`commitPlan` + journal），这是安全取舍；不为了「能导入」放宽成部分写入。
5. **在线更新后旧档可直接读**：更新流程不得要求玩家先导出行囊；`catalog` 只换文件，不重置存档。

## 残余限制

- 老版本（4.0.14 及更早）的行囊若含当前校验器不接受的字段，仍会整包拒绝；按作者要求**不为老版本加兼容分支**。
- 兼容专项覆盖的是行囊（导出/导入）路径，不是「4.0.13→4.0.16 的直接升级」全链路真机验证；真机升级由作者测试。
- 未做「格式版本升级后的自动迁移」用例，因为当前不存在 v4 格式。

## 边界

只新增测试与文档，**未改运行源码**、未改 `catalog.js`、未推送；本地 4.0.16 开发提交。
