# 批量赠礼UI独立交叉复核（2026-10-29）

复核者：bag_ui 子代理，未修改主线共享源码。安装版本4.1.0不变。测试只使用隔离真实无名杀宿主、临时Chrome profile/IDB、localhost只读服务。为访问IIFE中的UI状态，仅在测试服务返回内容中导出引用，不修改生产HTML。

## 已发现并由主代理修复

对桥兜底报价控制回调顺序，结果数据仍由真实宿主`giftQuote`生成，最初确认三种竞态：

1. 请求10份报价后改为50份，迟到回调恢复10份确认区。
2. 请求报价后切换人物，回调迟到；返回原人物时重新出现本应作废的旧确认。
3. 连续两次报价，后请求先回复、前请求后回复，旧回调覆写新CID。

主代理新增`giftQuoteSeq`，报价开始与数量/人物变化使旧请求失效；回调同时核对请求代次、当前人物、当前数量与存档允许状态。独立同场景测试由**9通过/3失败 → 12通过/0失败**，两组均无运行异常，测试始终未扣款。

## 用户侧正常路径

- 原生选择“自定义”，输入框自动获得焦点；输入27不重绘丢焦点。
- 原生点击礼物后准确生成27份/总额/收益的聚合确认。
- 640×286确认按钮真实位于资料滚动区可见边界内，正确获得焦点，`elementFromPoint`命中。
- 原生取消不扣款，焦点回到数量选择器。
- 最终追加原生左右键在数量输入框编辑时不切换收礼人物，最终扩展测试**13/0**（见`gift-cross-final/host-smoke.json`）。

复核源码中确认保留：交易进行中禁止重新赠礼、重复确认、数量修改；切换人物不把旧成功反馈显示给新人物；失败保留同一请求以供重试。实际扣款、丢ACK、quota失败/修复、满羁绊减量由主代理完整宿主测试及另一代理数据复核负责，本UI报告不重复冒认其独立证据。
