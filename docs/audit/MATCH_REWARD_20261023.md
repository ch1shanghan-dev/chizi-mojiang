## 结算边界

- 只有实际 `gameStart` 观察事件建立随机 run ID，同一局重复事件不重置。ID 使用 `crypto.getRandomValues`；缺失安全随机源时保守不发放。
- 本局必须观察到至少一次有真实场上/死亡玩家归属的 `phaseBefore`、`useCardAfter`、`respondAfter` 或 `damageEnd`，不设等待时间。没有开局/没有实际回合或动作、对象不属于对局、异常离开均不会发放。
- 只接受原生 `game.over` 第一个参数严格为 `true` 或 `false`；其他参数格式按未确认结局收尾，不猜测胜者。局开始模式与终局模式必须相同。
- 收尾先冻结 run ID、模式、胜负与金额，随后调用 `wallet.settleMatch`。重复 `over` 无法重建奖励；金额为 0 不创建支付。余额与 receipt 原子持久化及流水重试由钱包负责。
- 回放、观战、联机、导入中、迁移恢复中及 saveGuard 禁写状态均拒绝奖励；正常录像初始化 `videoInited` 不作为回放。钱包采用新快照前调用无参 `invalidate()`，清理旧局及旧补领，并递增会话 generation。已经见过的旧 `gameStart` 事件不能在恢复后重建局；新的开局事件可正常建局。页面离开/刷新永久作废当前观察实例。
- 支付失败只保留内存中的已确认结局，可在当前设置页“补领本次奖励”重试。`retryPending()` 不接受外部指定奖励，配置变化不会改变已冻结金额。重载/导入后不把旧内存补领带入新存档；迟到 ACK generation 不符不提示，也不修改新会话状态。
- 新增 `game.over` 包装函数体只引用宿主 `game`、全局 `console` 与自身函数名，前层函数/采集入口挂 `game` 属性；保留调用时 `this`、完整参数与前层返回值。序列化给未安装扩展的客户端时可回落其本地原生 `game.over`。与统计、成就、讨伐已有包装共存，不替换其指针或采集规则。
