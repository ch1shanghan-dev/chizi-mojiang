# 行囊打包与恢复交互重构（2026-10-22）

本轮只改 `games/save.html`，新增 `tools/probe_bag_flow_rebuild.mjs`。迁移/壳的严格读取修复由主线程完成。保留既有未提交改动，不提交、不发布、不升版，不访问用户真实存档。

## 事实与根因

- `core/csh_migrate.js` 的 `exportCode()` 无选域参数：按 KEY_DEFS 全量采集、清洗、略过 null/undefined。不能把只读家当清单伪装成可自由删域的选择器。导出不消费、不删除本机进度。
- 后端没有整包数量/容量配额；各清洗器有字段自身的校验和钳制。页面如实显示全部范围、已使用类数、输出字符数及真实 Blob 字节数，不编造容量限制。备份上限真实来源是 `MAX_BACKUPS = 3`。
- 原页面把33类清点放在操作前，打包、复制、校验、导入共用同一按钮排；当前范围、预览与真正写入步骤不清。底部说明、备份、重置常驻占据正文。
- 原页面没有请求在途锁；连续点击会发出重复导出/重复确认。校验回包没有复核当前输入，旧码验证完成后能把已修改的输入误标为已验证。宿主已有事务锁不能替代这些页面状态约束。
- `inventory()`原先默认`collect()`为软读取，错误可退成空项；页面无法知道“0”其实是读取失败。主线程改为严格采集，并让 inventory/backups 桥捕获失败、明确失败 ACK。

## 最终行为

- 正常导出两次主要操作：一键打包 → 复制存档码或保存文件。文件使用标准 Blob / download，无远端服务；打包结果保留在可编辑框内。
- 导入三次主要操作：导入存档（先校验预览）→ 确认导入 → 宿主 UIKit 确认。保留独立“只校验”入口、差异预览、导入前备份；真正提交前再次核对同一份存档码。
- 宽屏两栏同时展示操作和清点；窄屏操作优先。备份/回滚、双确认重置、边界说明均放入可展开区域。未完成操作恢复位于这些折叠区之前，恢复期间仍能看到并点击。
- 导出/校验/导入/回滚/恢复/重置在途锁定相冲突动作；确认取消或回包后释放。未知写入结果保持恢复提示；宿主 busy 时禁用并轮询清点，结束后提示核对数值与备份。卸载页面停止轮询及页面回调。
- 读取失败保留上次值，禁用打包并说明如何重读；失败不画成空备份或零余额。成功恢复或回滚会清除旧预览。旧输入的迟到校验、旧页面回包不会改变当前有效操作状态。
