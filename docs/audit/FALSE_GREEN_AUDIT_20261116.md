## 0. 审计方法与结论

**方法**：274 个探针中 270 个读源码、223 个用 `.includes()` —— 静态断言是主流。对每一类高风险模式（路径基准、覆盖顺序、硬编码集合、模块层≠玩家层、改前判红形式化、死按钮）做「静态断言 → 运行时真值」的逐项复问；对代理初判逐条交叉核实，**剔除 3 条误报**（见 §4）。

**结论**：找到 **2 项确凿假绿/功能缺口**、**3 项需真机确认的可疑**、若干「如实标注的未实现」（不算假绿）。整仓 exit=0 不代表没有功能缺口——本次两项都是现有 210+ 断言全绿的情况下查出来的。

## 1. 确凿项（建议修，尚未修）

### 1.1 【真 BUG·中高】迁移存档后 5 个新互动当天可重复刷好感

**证据**：
- `core/csh_affection.js:126`：`const DAILY_KEYS = ["hunt","hold","gift", ...AFF_ACTS.filter(a => a.key !== "greet").map(a => a.key)]` —— **从 AFF_ACTS 自动派生**，共 22 键（含 lantern/bookmark/memo/quiet/seeoff）。
- `core/csh_migrate.js:890`：`var AFF_DAILY_KEYS = ["hunt","hold","talk",...,"waist","knee"]` —— **硬编码 17 键，漏了 5 个新互动**。
- `core/csh_migrate.js:911-913`：`cleanAffection()` 的 `day` 字段只遍历这份硬编码表，`e.day[lantern/bookmark/memo/quiet/seeoff]` 在导出/导入时被静默丢弃。
- 实测：`迁移器 AFF_DAILY_KEYS 数量: 17`；`lantern=false bookmark=false memo=false quiet=false seeoff=false`。

**玩家遇到什么**：玩家今天做了「同提一盏灯 / 夹一枚书签 / 记下她随口一句 / 陪她安静一会儿 / 送她到门口」，导出存档再导入（换设备/行囊迁移/换档恢复），这 5 项变回"今天没做过" → **同一天可各再做一次，白刷好感与回礼钱**。其余 15 项不受影响。

**为什么绿**：所有装扮/好感探针都测 `AFF_ACTS`、`stDay()`、`DAILY_KEYS` 的派生逻辑；**没有任何探针把「核心 DAILY_KEYS」与「迁移器 AFF_DAILY_KEYS」做集合对比**，也没有「带新互动日键的存档 round-trip」断言。

**建议修复**：`csh_migrate.js` 不要再硬编码这份表——从 `lib.cshAffection.DAILY_KEYS`（导出它）取真值；取不到时用包含新 5 项的兜底表。新增门禁：构造含全部 22 个日键的存档 → `cleanAffection` → 断言 22 键全保留（改前判红）。

### 1.2 【覆盖缺口·中】图鉴本地降级互动表 7 项 vs 核心 20 项，无探针对照

**证据**：
- `core/csh_affection.js:63-95` `AFF_ACTS` 实测 **20 项**（greet/talk/head/close/tea/stars/callname/dance/walk/share/photo/rest/promise/waist/knee/lantern/bookmark/memo/quiet/seeoff）。
- `games/codex.html:699` 本地兜底 `AFF.acts` 只有 **7 项**（greet/talk/head/close/tea/stars/callname）。
- `games/codex.html:938`：`var actionList = actionApi && Array.isArray(actionApi.AFF_ACTS) ? actionApi.AFF_ACTS : AFF.acts;` —— 桥不可用时用本地 7 项。
- `tools/probe_codex_scroll_20261114.mjs:52` 用 `Array.from({length:12})` 造了 12 个**假按钮**做几何测试；**没有任何探针校验真实渲染的互动按钮数 == 核心 AFF_ACTS 数**。

**玩家遇到什么**：从宿主正常进入时 `affApi()` 有值，看到 20 项，没问题；但独立打开图鉴页 / 宿主桥未就绪时（作者有时这样截图/调试），只看到 7 项，**13 项互动凭空消失**（含共舞/搂腰/摸腿/同提一盏灯等）。且页面此时本就显示「宿主未连接，仅可查看」，玩家难以判断是"功能没有"还是"没连上"。

**为什么绿**：E95BC 验的是 `csh_affection` 模块层的 20 项与台词库；E95BE 验的是几何可达；两者都不检查页面降级表与核心表的一致性。

**建议修复**：让 `codex.html` 的本地兜底表从核心模块导入（或至少与 20 项同步）；新增门禁断言「两个来源的 key 集合相同」。

## 3. 静态断言密度统计（不是 bug，但是风险面）

| 指标 | 数量 |
|---|---|
| 探针总数 | 274 |
| 读源码 (`readFileSync`) | 270 (98.5%) |
| 至少含一条 `.includes()`/`.test()` 静态断言 | 223 (81%) |
| **严格纯静态**（断言全是源码字符串、无任何运行时） | **1**（`probe_alert_status_20261113.mjs`） |
| 用真实浏览器 / VM | 58 / 149 |
| 声称「改前判红」且真构造反例 | 20 / 24 |

**修正后的解读**：不能说「81% 的门禁是静态的」——第二个审计代理逐文件核实后确认，**严格纯静态探针只剩 1 个**，绝大多数探针都同时有 VM 或浏览器运行时断言（历史 5 次假绿后做过一轮系统性整改，源码里都留了「口径纠偏」注释）。准确说法是：**81% 的探针"混有"静态断言**，这些静态断言本身不会单独造成假绿，但当它们断言的是「某个集合/文案存在即正确」而运行时部分没覆盖同一件事时，就成了盲区——**本报告两项确凿发现正是这种形态**。

**剩余可疑的静态断言模式**（代理扫出 25 条，交叉核实后保留为"关注项"，不定性为 bug）：
- 源码 `indexOf` 顺序断言运行时时序：`probe_room_journal_20261109.mjs:244`、`probe_texas_topup_20261107.mjs:195` —— 但两探针分别有 137/57 条断言 + VM 运行时，**有兜底**，风险中低。
- 只量测列表前几项：`probe_achievement_album.mjs:11` `slice(0,6)` —— 成就列表是同构行卡片，量 6 行代表性够，且用真实浏览器，风险低。
- 「函数/导出存在即判接线正确」：如 `probe_spirit_buffs_wired:208`、`probe_career_world_first_capture:117-118`、`probe_feedback_error_boundary:187/190` —— 建议后续补运行时验证，但当前无证据表明对应功能实际失效。
