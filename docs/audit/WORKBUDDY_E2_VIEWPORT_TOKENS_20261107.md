# E2 · 横屏视口令牌纠偏与断点基线锁定（设计方案 §4.1）

日期：2026-11-07。版本仍 **4.0.16**，未推送、未合并 main、未发版。未使用子代理。

## 方案与代码事实的两处偏差

方案 §4.1 写「16 个文件各写 `330/500/760px` 混用 → 统一 `--csh-vp-short:420px`」。
全仓实测后两条都不成立：

1. **330 / 500 不是混用，是有意的两档**。`max-height:330px` 出现在 5 处，
   是极矮横屏（640×286）的**额外收缩**；`max-height:500px` 出现在 6 处，
   是一般矮横屏（915×412 / 844×390）的常规收缩。合并成 420 会让 640×286
   拿不到额外收缩，牌桌主操作与公共牌被挤出首屏，直接违反 §4.2。
2. **断点不是 3 种，是 24 种**。扫描全部 `core/` + `games/` 的 css/html，
   `max-height/max-width` 数值共 24 种：
   `330,340,350,400,420,430,440,450,480,500,520,540,559,560,600,620,640,720,750,760,899,1000,1199,599`
   （其中 430 出现 21 次、600 出现 8 次、640/1000 各 6 次）。
   一次性收敛要同时改动十几页布局，每页都要重跑 640×286 / 915×412 / 1365×768
   三横屏 + 1.5 缩放截图比对，风险远大于本轮收益。

## 本轮做法：统一口径，不动数值

| 文件 | 改动 |
| --- | --- |
| `core/csh_viewport.js`（新） | IIFE 挂 `window.CSHViewport`：`TOKENS`（330/500/760 + 桌面下限 1365×768）、四档 `PROFILES`、`classify(w,h)` → `vp-desktop/vp-wide/vp-tiny/vp-portrait`、`isDesktopLayout()`、`isLandscapePhone()`。非法输入返回 null，不默认放行 |
| `core/csh_layout.css` | `:root` 加 `--csh-vp-tiny-h:330px` / `--csh-vp-short-h:500px` / `--csh-vp-narrow-w:760px`，注释写明两档不可合并与 §4.3 定则（media query 不能用 `var()`，此组为文档与未来 `@custom-media` 迁移的单一来源） |
| `tools/probe_viewport_tokens_20261107.mjs`（新） | **35/0 ×2**，改前基线 1 红 |
| `tools/check.js` | 注册门禁 **E95X**（min 35） |
| `catalog.js` | 1041 → **1042** |

**零布局风险**：没有改任何一处现有 `@media` 数值，只建立唯一真值与约束。

### 门禁怎么锁

探针把 24 种历史值固化成 `BASELINE` 白名单，断言全仓扫描值集合 ⊆ 基线；
新增任何基线外数值立即判红，提示先走视口令牌与截图验证。同时断言
330/500/760 三档主值仍在使用（没被误删）、基线恰为 24 种（防止有人偷偷扩表）。
这与项目 B11 的静态基线策略一致：先锁住「不扩散」，再分批改。

### art-direction §4.3 做成硬断言

「手机横屏比桌面断点宽」——`isDesktopLayout(915,412)` / `(1200,500)` / `(1365,600)`
必须为 false，只有同时满足 1365×768 才是桌面档；边界 1364×768、1365×767 也不是桌面。
改前基线把判定改成 `w>=760 就套桌面`，断言集立即判红。
