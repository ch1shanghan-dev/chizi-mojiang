# 安卓4.0.13在线更新故障：分析、开发修复与交付待办

2026-11-05。作者提供两张截图并确认来自安卓手机/平板。旧客户端显示4.0.13，远端4.0.14；本轮开发副本为4.0.15，未升版、提交、推送或安装到安卓。正式PC安装关键文件未变。本轮工作记录不等于手机已经恢复更新。

## 截图事实

五条线路能读取版本信息，但执行后README.md、core/_census.mjs、core/csh_achievement_album.css失败，原因显示[object Object]。另一横屏状态标题/顶部内容被裁切，按钮被宿主装饰挤占。线路绿色只代表版本探测成功，不代表下载、创建目录和写入全过程成功。

## 根因证据与界限

1. **已复现：安卓目录创建竞态。** 实际宿主noname/init/cordova.js的ensureDirectory会启动递归getDirectory后立即调用callback/resolve，未等待目录完成。4.0.13更新器await该回调后立即resolveLocalFileSystemURL(base+dir)写入，可能遇到尚未存在的目录。用git 782b9e9中的4.0.13更新器与本机实际Cordova ensureDirectory函数、异步DirectoryEntry隔离复现：目录创建和三并发暂存两项失败，缺失原文件读取通过。
2. **源码确认：错误对象被直接字符串化。** FileError或FileWriter事件对象没有message时，String(e.message||e)得到[object Object]，掩盖存储/权限/目录原因。截图三个文件同时失败与并发暂存路径一致。该竞态是已复现的故障机制；未取得用户安卓日志，不宣称它是现场唯一故障。
3. **UI源码问题。** 原样式仅有100dvh最大高度，没有旧WebView可用的100vh回退；完整五线路和长错误全部堆在主体里；按钮未隔离宿主伪元素装饰。结合截图裁切，旧WebView高度支持、宿主样式与内容挤占是需共同处理的布局因素，不能仅从图片确定用户WebView版本。
4. **当前官方文件只读核对。** 本电脑访问main目录得到4.0.14，截图三个文件HTTP200且哈希均与官方目录一致；这是本电脑网络的事实，不替代安卓网络/CORS验证。没有放宽联网来源、重定向策略、下载上限或文件摘要校验。

## 本轮已修复（开发副本）

- Cordova写入从真实根DirectoryEntry开始，逐层等待getDirectory(create:true)成功，不依赖宿主提前返回的ensureDirectory。并发任务可共享已有父目录。
- FileWriter错误后锁定失败状态，忽略随后onwriteend，不在错误后继续truncate。保留短文件截断与写后哈希核验。
- 增加循环安全的嵌套错误提取和errorText；区分找不到文件/权限/空间配额/取消/未知事件，不打印对象字符串。不把读取权限错误当作文件不存在。
- 更新核对显示文件进度；提交/恢复关键阶段避免关闭中断原有流程。
- 弹窗横屏高度同时支持vh/dvh；线路默认折叠，可展开切换。标题紧凑，四个动作保持44px可达，清除宿主按钮伪元素和背景装饰。
- 主状态只显示结果和下一步，具体失败文件/原因放“查看失败原因”按需展开；长内容在弹窗内滚动，标题和关闭/恢复按钮不被裁掉。
