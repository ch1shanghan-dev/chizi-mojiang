## 建议施工顺序

先只读取现有后端/反代/表结构并形成记录，确认可复用部分；不要把“本仓库没找到后端”理解成服务器没有服务。建立隔离测试库，以合成数据验证备份恢复和迁移；域名、证书、公开接口、CORS及缓存策略各自验收。服务能力描述应有固定schema、服务ID、协议版本和明确只读能力，不下发可执行脚本或任意下载来源。

P2A先接公开榜，验证国内网络、Android/WebView的Origin和证书链、超时/429/5xx及退避，再审受控环境回滚。客户端按服务/协议隔离旧快照，切换前保留旧记录和客户端完整安装包；新服失效时保持本地玩法。

P2B再做写认证：安装身份和服务端凭据分开，凭据按服务存储且不进入可分享存档。明确旧UID映射证据，不能按昵称、同IP、指纹或公开UID冒认。服务端对成绩取合法峰值并去重；旧客户端的自报写路径不能绕过新权限。CBY/功勋属本地自报，不能包装成可信竞技认证。

P2C全球应援需服务端以可信身份+CID在持久事务里去重，同时保存贡献和可重复查询回执；相同CID不同负载明确拒绝。验证客户端已扣款→响应丢失→重试、服务重启、多设备身份恢复、重放、迁移及迟到ACK。客户端沿用原钱包outbox，只有对应服务和归属确认后才能清除，绝不重新扣款。

P3公告与版本为附加只读元数据，独立失败预算、缓存和来源校验。复用现有更新器及GitHub路径，同版本看构建摘要。先通过离线/更新失败/旧客户端兼容演练，生产部署、DNS和发布安排到具体配置可审查后执行。

## 停服与回滚

服务停止时不强制登录、不阻塞启动、不清本地资产；快照带日期，历史应援继续保留。服务端先恢复经验证备份/旧程序，客户端先关闭联网；不要靠恢复旧全量玩家档来回滚一个在线视图。换服必须有可信身份和CID映射，否则只读保留旧意图。永久停服的退款/本地补偿属于经济规则另案，当前没有自动实施。

逐文件客户端更新尚非原子目录切换；强杀/断电情况下扩展未必能加载自救。应保留完整包和人工恢复流程，不能把本轮离线保障解释为该问题已解决。
