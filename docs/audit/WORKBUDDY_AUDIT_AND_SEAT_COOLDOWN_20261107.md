## 7. 本轮推进的待办：世界同桌跨桌冷却（方案 §3.2 纠偏实施）

方案原文定案「0–49 全池 / 50–99 排除已退隐 / 100–149 冷却 1 桌 / 150+ 冷却 2 桌」，
实测 `core/csh_world.js:activeList()` **早就无条件 `!a.retired && fund >= AI_MIN_STAKE`**，
`seat()` 候选池天然排除退隐——照方案做前两档等于没有改动。
原文「退隐越多，跨桌重复概率越低」的因果也是反的：**缩小候选池只会提高重复率**。
真正缺的只有「同一角色不连续出现在相邻几桌」的冷却。

实现（不碰钱包、不碰战斗引擎、不改世界存档结构）：

| 文件 | 改动 |
| --- | --- |
| `core/csh_seat_cooldown.js`（新） | IIFE 纯函数：`cooldownTables(retired)` → 0/1/2 桌；`filter(pool, history, tables)` 只排除最近 N 桌的 id，**候选全被挡时降级回完整池**；`push()` 有界历史，不改入参 |
| `core/csh_world.js` | `seat()` 三处接线：算当前退隐人数 → 过滤候选池 → 组桌后记录最近 2 桌。全部 `if (SC)` 守卫，模块缺失降级为原有行为 |
| `tools/probe_seat_cooldown_20261107.mjs`（新） | **42/0 ×2**，改前基线 2 红 |
| `tools/check.js` | 注册门禁 **E95T**（min 42） |
| `catalog.js` | 1037 → **1038**，0 不符 |

分档按事实重定：**退隐 0–99 → 0 桌（零回归）/ 100–149 → 1 桌 / 150+ → 2 桌**。
只过滤候选池；已入座者的 stake / skill / persona / 发牌、桌级四档一律不动
（反例里对接线片段做了「无 stake/skill/persona 赋值」的静态断言）。

反例覆盖：8 个分档边界、7 类非法输入、冷却 0/1/2 桌、只取末尾 N 桌、候选全挡降级、
入参不变、原型键 id、空池、有界历史、连续三桌组合流程、6 条接线静态断言、
改前实现判红。改动后 E95F 67/0、E95H 35/0 与慢速通道 8/0 均无回归。
