# 妖灵主人边界与迟到支援修复（2026-10-29）

本分支只修改 `core/csh_aux_spirit.js` 三个支援技能的执行期守卫，新增 `tools/probe_spirit_owner_boundaries.mjs`。版本4.1.0不变，未提交、推送或发布。`main/content.js`、所有武将/卡牌/技能文件、图音、钱包/迁移和其他共享核心均未由本分支修改。

## 本来已有且本次实际复核的行为

这次没有重新实现“阵亡移出行动列表”：原生妖灵死亡原本就会退出 `game.players`，进入 `game.dead`，保留死亡节点和原席位；再次调用start不会补召，原生revive会回到存活列表且保留本局剩余配额。

完整宿主本轮首次连贯验证：妖灵原生 `die/revive` → 主人原生 `die/revive` → 直接身份变更 → 原生 `swapControl` 切出/切回。主人死亡时妖灵仍以原身份存活，对主人的支援停止；主人复活后仅恢复剩余配额。身份/控制变化有明确暂停原因，切回合法主人恢复支援，原生接管妖灵本人仍被阻止。钱包余额与辅助分类均不变化。

使用普通四人身份局，临时配置屏蔽主公和内奸给测试主人，因而主人原生死亡不会直接触发主公阵亡终局。本轮没有屏蔽、替换宿主胜负判断或死亡钩子。所有角色/手牌/次数初值仅来自隔离测试fixture，不作为自然实战或50位逐人通过证据。

## 新复现的问题

支援filter已有充分条件，但执行content仍信任旧filter结果。

1. 护主content直接减伤和增加已用次数，若排队后主人身份/控制/存档代次等变化，即使状态已经暂停，仍会减伤并消耗额度。
2. 同契content先置已用，再读取合法主人；暂停后虽不回复，唯一一次额度已经白耗。
3. 助战在执行期重新寻找主人，但不重新核对三次上限；已用完三次的迟到执行仍可第4次摸牌。护主/同契也缺少相同执行期配额核对。

新31项执行专项修前12通过/19失败。七类失效状态（身份/控制/主人死亡/妖灵死亡/恢复中/钱包代次/终局）分别检查护主、助战、同契；另覆盖额度已被占用、目标换成旁人、伤害归零/脱离濒死、复活保剩余次数和正常原效果。

完整真实引擎通过 `game.createEvent` 排队原技能content，受控模拟filter后状态变化，实际复现三组错误：暂停仍把2点伤害减为1点、暂停仍把同契标成已用、已耗尽的护主/助战次数变成4。该完整宿主同链结果修前16通过/3失败，无运行异常。这是执行真实子事件的故障注入，不声称自然对局已经观测到具体竞态发生频率。

## 修复

- 护主content执行前复用现有filter，重新确认原主人、会话、有效伤害与剩余配额。
- 助战content保留原主人检查，追加已用次数小于3的执行期条件。
- 同契content先复用现有filter并取得仍合法的主人，之后才消费唯一额度、回复原有1点体力。

没有改变触发点、3/3/1配额、减伤/摸牌/回复数值、身份/胜负规则、默认关闭行为或战斗AI。`source-proof.json`通过逆向替换验证整文件除了这三处content守卫逐字相同；修改前后SHA分别为d4c3db09…c7471ef、6c4b25c2…3839b。
