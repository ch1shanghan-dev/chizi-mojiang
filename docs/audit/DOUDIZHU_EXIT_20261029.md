# 斗地主关闭、收工与再来一局边界修复

2026-10-29。本分支仅修改 `games/doudizhu/doudizhu.html`、新增 `tools/probe_doudizhu_round_boundaries.mjs`。4.1.0不变，未提交或发布。报告、备份与浏览器产物留在扩展之外。普通武将AI、牌规/组合规划、费率、奖励和美术资源未改。

## 复现与根因

修前同一组真实函数执行探针为16通过/15失败。关闭结算等待期间，`startGame/newGame/showStart`还可清空或替换原局；“再来一局”和“关闭”各自向同一transport挂回调，一份成功ACK可同时reload和close；重复再来会挂多个reload。`closePage`失败回调不判断teardown，已离开的iframe可能被恢复为alive，成功迟到回调仍可能向宿主发关闭协议。单独运行的重复关闭也会重复window.close。

## 实施

- 新增 `leavePage(reload)`，关闭、收工和再来共用一个退出锁；等待时停掉递归计时，成功仅执行一个去向，重复回调无效。
- `tornDown`区分“暂停等结算”与“页面已销毁”。销毁后迟到成功/失败ACK都不再reload、复活或发关闭消息。
- 新开、重发、返回开局、托管开关在退出等待或页面失活时不修改牌局。原正常返回、重发、接管和独立小游戏保留。
- 失败后释放锁、保留原局，恢复当前叫分/出牌等待并显示重试说明。超时后晚ACK由实际共享transport丢弃，重试仍走原会话幂等凭据。
- 原“再来”保留 `Bridge.settle`，关闭/收工走已有 `Bridge.settleSession`，所有金额和宿主计费参数不变；“收工”收敛为关闭，避免独立的未保护回调。

`source-proof.json`验证规则引擎全文逐字一致、CSS和页面标记一致，96个函数仅10个预期生命周期函数（含新helper/内部finish）发生变化，无额外函数差异。

## 验收

- 新专项：改前16/15，改后31/0。执行真实斗地主引擎、Bridge、生命周期和共享 `csh_page.transport`；受控ACK/计时器覆盖关窗与再来互斥、连点、失败/data.ok=false/超时重试、旧ACK、卸载后迟到、原筹码/席位、独立重开、跨轮及托管取消。
- 真实隔离宿主：10/0，无运行异常。通过实际宿主/钱包原生开局，使用合成终局触发真实结算，暂存真实成功ACK，原生点“收工结算/再来一局”仍保留原结果；释放ACK后才关闭，期间没有重复收费/入账。截图 `host/pending-close.png`。
- 原原生接管宿主：14/0，无运行异常；斗地主/UNO提示、托管开关、Esc快速接管、取消队列与两横屏尺寸均通过。
- 原规划基础：42/0；原1000局规划44/0，斗地主45883动作、UNO39167动作，无非法/停滞失败，观测max 38.67ms、p95 3.67ms（机器本次测量，不是实体设备性能承诺）。
- 新工具语法、限定文件diff空白检查通过。

真实宿主仅在只读测试服务器响应注入诊断接口和ACK暂存，发布HTML无测试接口。隔离IDB/Chrome profile不读取玩家存档。为了原生点击有稳定窗口，测试器仅在暂存时延长4000ms transport超时至15000ms；新执行探针另覆盖原4000ms超时回调。

最初执行探针缺少 `requireSave/nextIdx`夹具、原规划抽取setAuto无closePending变量，均已适配后保留原断言。第一次宿主未用网络权限时fetch失败；第一次原生壳X在宿主已落账时按既有逻辑直接移除frame，并不等待子页ACK，因此测试改为确实调用本页关闭路径的“收工结算”。不把这些环境/夹具失败计作业务通过；原始日志保留。

## 边界

本批不建立跨进程房间恢复，不宣称Android/WebView/Electron实体设备或完整自然牌局通过。宿主已经收到并落账的成功结算时，壳顶X仍按既有逻辑直接关闭，这不会丢账；本批修复的是本页未获ACK时的重入和迟到回调。原规则引擎/AI未变，基础策略合法性不等于最佳策略。

复现：`node tools/probe_doudizhu_round_boundaries.mjs --out <扩展外结果.json>`；修前增加 `--source <本目录/before.html>`。可选 `--root`。
