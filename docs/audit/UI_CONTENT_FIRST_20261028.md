## UI验收补充

1. **第一眼看到主体。** 成就以成就卡/进度为主体，世界以人物和事件为主体，牌桌以手牌/公共牌/筹码/行动区为主体；标题、栏目说明、统计总数和装饰不能算作主体面积。列表不能只剩一条缝，让玩家先滚过几屏说明才能操作。
2. **标题紧凑。** 常规标题一行，与返回/必要操作共用一条短头部；不另加大型欢迎区、重复页名、口号、厚分隔和大块空白。文本字号要有层级，但不靠超大标题营造质感。
3. **导航和工具条合并。** 搜索、筛选、排序与批领使用紧凑操作位；次要筛选、详细统计、规则和本机设置按需展开。展开后必须容易收回；费用、奖励和失败信息仍在相关操作旁清楚可见。
4. **钱包与关闭分开。** 一级需要钱包处显示一份紧凑余额；子页避免重复展示。关闭按钮保留独立安全点击区，不能与余额、领取按钮、页内标题或装饰重叠。
5. **主体面积可测。** 将主体可见区域与当前可用视口求交，扣除覆盖其上的控件。常规电脑首屏以主体约75%以上、手机横屏约65%以上为设计目标；这些是后续设计目标，不是现有页面已通过的比例。极矮屏640×286单独压缩导航，允许必要外层滚动；偏离目标要记录原因及可达操作，不能通过缩小正文/触控区域或把标题算成主体来凑数。
6. **清晰与密度一起验。** 辅助文字沿用至少12px标尺，主操作触控区域保持约44px；先消除重复信息、无意义字段和过厚间距，再调整字号。列表自适应分列，长文本合理换行，不截断奖励和关键条件。软键盘展开后当前输入及确认动作可达。
7. **美观来自完整设计。** 统一字阶、色阶、材质、图标、对齐与留白；东方奇幻/金石漆器作为提案方向，复用现有六套皮肤与合法素材。局部纹理、印章、奖章和按钮反馈服务于主体，不用满屏光晕、边框、胶囊或大背景占位代替设计。
8. **动效让出操作区。** 解锁/晋升/礼物反馈靠近相关内容，不能遮手牌、行动按钮和滚动列表；有数量预算、跳过与减少动效。交易完成和动画展示分别处理，不因动画关闭、双击或迟到回包重复结算。

## 按模块的主体与布局方向（待后续施工验证）

| 模块 | 主体 | 优先排版方式 |
| --- | --- | --- |
| 生涯/成就 | 成就卡、进度、奖励状态 | 顶部短标题+紧凑工具条；批领独立操作位；手机不保留挤压内容的宽侧栏；搜索筛选可收纳 |
| 池子世界 | 角色、事件、互动回应 | 主内容直接可见；身份/关系/任务摘要合并；故事和回忆按需展开 |
| 妖灵图鉴 | 人物主视觉与当前互动 | 横屏人物和内容合理分栏；对话/礼物/故事切换；不把所有亲密度和规则叠成头部 |
| 德州及其他牌桌 | 牌、筹码、底池、合法动作 | 状态文字贴近座位且去重复姓名前缀；头像/气泡不压手牌；出局观战与活跃座位分开呈现，规则座位仍稳定 |
| 池子调试 | 当前分组可操作工具 | 短拖动栏、可折叠分组与搜索；拖动与点击分开；素版/懒人包分别核实，不能仅凭截图猜根因 |
| 行囊 | 备份/导出/导入与预览 | 核心操作直接可见；档案诊断和内部键域折叠；覆盖/费用/失败提示保留在动作旁 |
| 官阶/战绩/挑战/市场/天下榜 | 当前成长、记录、战况、交易或排名 | 只保留与当前任务有关的摘要，不堆巨型总览横幅；复用共享列表、状态和操作规范 |

## 验证方式

电脑1280×720、1366×768、1920×1080；手机915×412、844×390、640×360、640×286，以横屏为主。任务书中的390×844/360×640保留为竖屏兜底，不覆盖横屏主验收。125%/150%宿主缩放、普通版/懒人包、真实Android/WebView和Electron按可用环境分别留证；未实测明确标待验。

后续每屏记录头部/导航/工具条高度、主体可见宽高/比例、遮挡面积、首屏内容与主要动作，提供同尺寸同状态前后图。另测长标题、大数额、待领奖励、无数据/加载/失败、折叠展开、键盘/触摸/ESC及关闭重开。旧170项横屏和36项联网宿主是对应轮次证据，不能当作本次新视觉目标全部达标。
