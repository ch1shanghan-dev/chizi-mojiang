# 非武将系统普查（2026-10-27）

## 结论与范围

本轮发现 **4 组可复现缺陷**：送礼/结契写失败后仍扣款、应援补报记录丢失、手机生涯导航被壳控件遮挡、页面换肤接线与样式顺序失效。前三组建议 P1，换肤建议 P2。另有 8 项体验/结构优化建议及真实设备/服务器验收空白。

本次是普查与计划，**没有修改业务代码或真实存档**，不把发现问题写成已修复。仅增加诊断工具与文档；上一轮本地成果全部保留，武将定义、战斗技能/AI、立绘/语音不在本轮审核或改动范围。版本仍为 4.0.12，HEAD c825879 上已有未提交改动，不提交、不推送、不发布。

普查覆盖 core、games、main 共 **60 个 JS/MJS/CSS/HTML 文件的目录、职责和风险入口扫描**，其中 core 41、main 8、games 11；对重点读写链做定向源码核对与故障验证。实际浏览器遍历了注册表的全部 11 页，分别取 1365×768、915×412、390×844，共 33 个初始/离线/列表状态；另测生涯页六皮肤及皮肤消息控制路径。这不代表逐行审完全部源码、全部小游戏自然终局或所有次级弹窗验收。

证据等级：R = 当前真实函数/浏览器中隔离复现；S = 当前源码确认；D = 设计建议；H = 尚需真实环境验证。备份、JSON 与截图全部在扩展目录外，公开报告不含玩家存档、凭据或个人主目录。

## 已确认缺陷

### NC-01 · 送礼/结契未形成共同事务（P1，R）

- 路径：妖灵图鉴 → 送礼或结契 → 钱包扣款 → 好感存档写入失败。
- 根因：csh_affection 的 lsPut 吞掉写入异常，writeStore 不返回状态；stAdd 和 oath 在未落盘时仍返回成功。送礼的回滚只判断 stAdd 是否返回对象，识别不了这类失败。
- 证据：实际钱包、好感模块、持久化键及隔离后端中，仅让 csh_affection 写入失败。送酒 API 返回成功且报告好感 5200，实际仍为 5000，钱包已持久扣除 **6000** 测试 CBY；结契 API 返回成功但未存 oath，钱包已扣 **1720000** 测试 CBY。正常送礼/结契两个对照都通过。
- 锚点：[lsPut/writeStore](../../core/csh_affection.js#L160)、[stAdd](../../core/csh_affection.js#L266)、[oath](../../core/csh_affection.js#L561)、[gift](../../core/csh_affection.js#L607)。
- 建议：付费好感操作复用钱包检查点模式，把扣款、好感/契约变化和业务收据作为可恢复的一次提交；至少要让所有写入方收到明确成功/失败，不能只补 try/catch。失败后重试、重载、流水恢复都按业务 ID 幂等。
- 保全：原好感值、偏好倍率、礼物价格、契约成本与已结契时间不变；不推断或补发无法证明的历史损失。
- 验收：正常操作一次付费一次生效；好感写失败、钱包写失败、断在两后端之间、补偿再失败、刷新重试均不丢款、不重复生效。

### NC-02 · 应援补报队列会丢未完成记录（P1，R/S）

三个独立缺口均在当前客户端，不依赖生产服务器扫描：

1. flushCheer 遇到 {ok:true, ignored:true} 仍移除队首。隔离模拟返回后，已付费待补项从 1 变成 0，与 doCheer 初次提交的 ignored 分支口径相反。
2. pendPush 使用 slice(-20)。已有 20 笔未完成记录时再入队，会静默丢掉最旧一笔；当前没有在扣费前拒绝第 21 笔的控制。
3. doCheer 先收到宿主扣款成功，随后发网络请求，只有失败回调才持久化补报。模拟网络请求开始后无回调（如关页）时，扣款 ACK 已发生，但新业务没有持久待报记录。

- 锚点：[pendPush/flushCheer/doCheer](../../games/rank.html#L1149)、[宿主扣款](../../core/csh_shell.js#L1764)。
- 建议：由宿主维护带 cid 的持久 outbox，扣款与待报收据同写；页面只展示进度。只有明确已受理且非 ignored 才清除，恢复/重试保持同一 cid；容量满时在扣费前明确阻止新付费，不能截断旧账。
- 验收：断网/限流/迟到 ACK/关闭重开/超过 20 笔/换档均保全记录，不重复扣款或上榜。客户端可先修；服务器 cid 幂等和身份认证仍需后端源码及隔离部署验收，不借此宣称服务端安全已完成。

### NC-03 · 手机生涯导航仍有壳安全区冲突（P1，R）

- 路径：390×844 → 生涯大厅。顶部导航第一行的“任务”文字矩形约 x=299.5、y=16.8、宽 28.6、高 20，与右上角余额控件重叠。
- 根因：早期移动布局预留 padding-top:48px；末尾通用 #tabs 修补把它覆盖为 14px 0，移动端规则没有恢复顶部安全区。根页面没有横向溢出，上一轮的领取/正文宽度断言无法检出这个遮挡。
- 锚点：[移动结构与后置修补](../../games/career.html#L512)、[壳控件](../../core/csh_shell.js#L1217)。
- 建议：将导航与壳安全区作为同一布局约束，给竖屏导航明确顶部安全区，避免把桌面侧栏 padding 无差别覆盖到移动网格；正文维持独立滚动。
- 验收：所有六个菜单的文字、计数及点击区域不与余额/关闭键重叠；长昵称、大余额、缩放、横竖屏与软键盘变化同时检查。

### NC-04 · 已打开页面的皮肤变更没有完整生效（P2，R/S）

- 第一层：csh_theme.setSkin 向主窗口自身 postMessage；csh_page 的监听器位于 iframe，未找到宿主向当前 iframe 转发的接线。实际切 warm/paper/celadon/night/gold 后，页面 csh-game-chrome 仍是旧样式。
- 第二层：手动从父页向 iframe 发原协议消息后，子页确实收到并生成暖纸变量，但样式插在后续 3 块页内 style 之前，页面定义覆盖它。暖纸预期 --ink-1 为 #E4D8C5，实际仍为 #101216。
- 锚点：[setSkin](../../core/csh_theme.js#L647)、[注入与监听](../../core/csh_page.js#L120)、[页面后置变量](../../games/career.html#L518)。
- 建议：先明确宿主皮肤与各游戏特色配色的契约，再建立当前 iframe 的定向消息和正确级联位置；避免新增通用 --ink 覆盖。固定深色特色区域应显式使用自身 token，正文与背景必须成对切换。
- 验收：已打开/新打开页、六皮肤、二级弹层均测“变量收到 → 实际计算值 → 文字对比度”，同时保留扑克颜色和游戏专属语义色。
- 排除误报：不透明成就卡当前标题/说明对比度约 **16.48:1 / 10.96:1**，并非六套全部低对比。初版对半透明卡只取 RGB 忽略合成背景的六项失败已作废，不计为缺陷。
