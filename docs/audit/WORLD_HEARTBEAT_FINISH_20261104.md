# 世界休闲心跳保存闭环收尾

日期：2026-11-04。单轮三代理批次中的世界子任务，版本4.0.14不变，不提交推送。仅负责core/csh_world.js的休闲心跳候选/保存协调、core/csh_debug.js休闲提示及专用探针；不扩展成进行中房间快照，不改随机桌数/资金参数/四桌收益规则。

## 当前已实装

- 心跳先在克隆世界中生成一次完整候选，包含原日期、额度、资金/关系、历史与批次最大底池；严格setItem并读回确认后采用，才返回成功和发布日志。
- 拒写/静默丢写/读回失败公开内存保持原基线，返回尚未保存；再次进入先重试原候选，不重新随机跑一批。恢复后原日期、原候选只接受一次。
- 钱包对象/存档代次、世界基线或恢复守卫变化时旧候选作废；外部有效更新优先采用，不能用候选覆盖新事实。
- 写入已成功但读回失败时，后续真实世界写入先协调采用磁盘候选，再执行该次操作，避免旧内存盖掉已存心跳；持续读取失败暂拒其他写入。
- 本轮新补的实际缺口：坏外部世界此前只拦第一次其他写入就移除屏障，第二次可覆盖坏数据；被拒心跳也可能提前移除同一屏障。现直到外部资料有效采用、原磁盘基线恢复或明确换档/重载，才释放协调屏障。
- 休闲入口失败显示“牌友记录尚未保存，请稍后重新进入重试”，仅接受后显示离线天数成功提示；不暴露JSON、epoch、路径或错误堆栈。

上述大部分候选/严格读回和UI提示在暂停前已留在工作树，本轮核实收尾并补交错保护，不把旧第一版重复计为新增机制。
