## 问题与证据

上批迁移提供了严格事务、原值恢复凭据及重试入口，但凭据尚存时，普通模块仍可接受新进度。典型路径是导入的 config 事务及补偿事务都失败，留下 `csh_migrate_recovery`，随后继续签到、加功勋、完成每日任务或让世界心跳推进；再次恢复原值时，这段新进度会被覆盖。

仅在保存函数拒绝不够：签到先改日期与连签，任务先增加进度并占用奖励，世界先改变资金、战绩及关系；保存晚拒绝仍会改变内存，调用方还可能发成功 ACK。市场另有已经排队的 Promise、IDB 同步和重试定时器，钱包有防抖及卸载保存。启动顺序也不能假设迁移模块已加载。

本批以改动前的五个实际文件作负对照，同一专项为 **9 PASS / 58 FAIL**；正对照见下表。旧文件保存在扩展目录之外：`D:/noname-audit-backups/chizi-mojiang/20261022-recovery-guard/`。负对照含新增接口契约，不能把全部失败都解释为独立用户缺陷。

## 修改与契约

`core/csh_wallet.js` 新增只读 `lib.cshWallet.saveGuard.blocked()` 和 `reason`。每次检查直接读取持久恢复凭据，再检查迁移的 `recoveryState().busy/pending`；凭据损坏或读取异常同样暂停写入。迁移模块未加载时，持久凭据仍有效，不需要新存储键。检查自身不会改变存档。

钱包入账、扣费、免票入场、签到、救济、功勋、任务、职业领奖、市场检查点及流水、完整性修补、旧键迁移、清流水和普通重载在改变内存前拒绝。原数值/布尔/数组 API 保持原类型，结构化 API 返回 `ok:false` 和恢复提示；任务桥另外明确返回失败，不能把空数组解释成成功。防抖回调、强制刷新及卸载保存也受保护。

迁移自身的 `flushSave({migration:true})` 只可越过当前迁移的 busy 标记，**不能越过持久恢复凭据**。它现在返回真实钱包写入结果，迁移据此中止未保存的钱包快照。原值恢复继续使用迁移的严格写入通道；事务中的 `reloadSave(snapshot,{memoryOnly:true})` 仍只采用已严格读取的快照，随后清理凭据再开放普通进度。不会形成“恢复必须保存、保存又被恢复锁住”的循环。

兑换码验签拥有实际异步计数 `cdk.busy()`。导入、回滚、重置、恢复以及导出在验签过程中明确拒绝，避免把待核销占位与未入账余额当成完整快照。验签完成回调再次检查恢复状态，失败不核销、不入账、不报兑换成功；只验签的查询不会占用或释放兑换计数。专项使用隔离的可控 Crypto Promise 验证时序，不声称完成真实签名学测试。

`core/csh_world.js` 在亲历结算、资金胜负、豪赌记录、恩怨、导入、离线心跳和模拟入口前暂停。启动的兼容整理不能落盘；`saveWorld` 保留最后一道保护。只读查询和迁移的快照采用保留。世界普通保存仍是原来的软存储契约，本批没有把配额失败改造成完整世界事务。

`core/csh_market.js` 在交易、每日结算和检查点同步前暂停；已经排队的同步微任务执行时再次检查，等待配置完成后也重查，不在暂停状态清检查点或安排后续重试。迁移原有的 `marketBusy` 仍阻止从正常未完成交易中取迁移快照，原子钱包检查点/配置同步契约保持。

`core/csh_shell.js` 对包含存档变化的消息先回复失败：结算、任务、功勋、签到、救济、成就领奖、市场、好感互动、缠头、悬赏、游戏开场及世界轮次/结果。失败结算不填入 `GUARD`，也不能再被无条件改成 `ok:true`；直接调用的结算及关壳好感/亲历同样有守卫。只读钱包、世界、账本查询、关闭以及行囊迁移命令继续可用，行囊/生涯等 `lobby` 页面仍能打开。失败 ACK 的完整中文由专项精确断言，避免出现编码损坏后仍“通过”的情况。
