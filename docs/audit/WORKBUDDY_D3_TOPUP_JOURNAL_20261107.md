# D3 · 补码未决事务与启动幂等退款（补齐 D2 的跨进程缺口）

日期：2026-11-07。版本仍 **4.0.16**，未推送、未合并 main、未发版。未使用子代理。

## 补的是什么洞

D2 报告明确留了一条未做：`csh_wallet.spendPC` 用 `scheduleSave()` **异步写盘**，
D2 只做到「内存读回确认」。极端情况下：

- 扣款已写盘，但页面没收到 ACK / 没上桌就崩 → 玩家平白损失一笔钱；
- 扣款**没**写盘，页面上桌了且随后把筹码结算回钱包 → 等于凭空造钱。

方案 §3.1 要求「绝不出现『扣了钱没上桌』或『上桌了没扣钱』」，D2 在跨进程层没兑现。
本轮按项目 U0—U4 的更新事务纪律补齐，不另造一套状态机语义。

## 事务设计

单本机键 `csh_topup_pending_v1`（已在 `csh_migrate.js` 的 EXCLUDED 登记，不随行囊迁移）：

| 阶段 | 动作 |
| --- | --- |
| `prepare` | **扣款之前**同步写 `prepared` 凭据并读回确认；写不进去就不扣款、不上桌。已存在别的未决事务时拒绝，同 id 幂等 |
| `spend` | 宿主走同一条 `wallet.spend` 出账路径，ACK 带 `txId` |
| 页面上桌 | 校验 `data.txId` 存在才允许 `chips += N; G.buyIn += N`；随后发 `shell-topup-commit` |
| `commit` | 宿主校验 id 匹配后清除凭据并读回确认；失败不清也不影响本局，留给启动恢复 |
| `recover` | 启动延迟一拍执行且只跑一次；发现未决凭据时按余额判断，**幂等退款** |

**头号不变量**：不能无条件退款。凭据里记 `balanceBefore`（扣款前余额），恢复时读当前 `pc()`：

| 重启后 `pc()` | 判定 | 动作 |
| --- | --- | --- |
| `balanceBefore - amount` | 扣款已持久化、页面没上桌 | 退款 `amount`，清凭据 |
| `balanceBefore` | 钱包写盘没成功 | **绝不退款**（否则白送钱），只清凭据 |
| 其他 | 期间有其他收支，无法判断 | 保守不退款，清凭据并如实记录 |

退款前先把凭据推进到 `refunding` 再动钱，中途崩溃重跑也知道钱可能已退；
`refunding` + 余额已回到 `balanceBefore` 时不重复退。`wallet.add` 被拒或读回不一致时
**保留凭据待重试**，不吞钱。凭据格式严格校验，篡改/损坏一律清键且不退款。

## 现在可以说的边界

D2 那条「跨进程写盘失败且进程中断」缺口已闭环：**扣款与上桌之间有任何中断，
下次启动都会把两侧拉回一致**，既不吞玩家的钱也不凭空造钱。多页面并发也被
`prepare` 的「已有别的未决事务则拒绝」挡住。
