# 待办方案 · 退隐/未接路由的「可靠首次采集」口径（2026-11-06）

## 为什么单独立项

B6 把交接里「当前退隐 26 条与世界其余指标、跨来源组合的可靠首次采集；旧日期未知留未知」
从一句含糊待办变成了**可量化的事实**：

| 分类 | 条数 | 首次来源 |
| --- | ---: | --- |
| 已接路由（worldHands 等） | 872 | 严格牌桌结算时间，已有 229/0 回归证据 |
| 退隐 `worldRetired` | 26 | **无** |
| 跨来源组合 | 1072 | **无** |
| 其余 AI 世界指标 / 彩蛋 | 30 | **无** |

合计 1128 条定义还没有可靠首次来源。B6 的 24/0 反例把「哪些没接」写死成断言，
并接入门禁 E58G，以后再有人悄悄改谓词分区会立刻被发现。

## 症状（不是独立 bug）

`core/csh_wallet.js:864` 的 `syncCareerUnlocks` 对没有 `sourceRecord` 日期、
也不是 `initial` / `historicalKeys` 的达成项，写 `observedAt = Date.now()`。
于是**非首次钱包**上，通用被动 `start()` 看到当前退隐已达 150 人，
会给 `cx_retired_...` 这类定义挂一个「此刻」的日期（B6 实测 `1793918714644`）。

这个日期是假的：它记录的是「第一次打开生涯页的时间」，不是「第一次达成的时间」。
同一份旧世界在首次采用（adopt）路径上，26 条退隐定义反而全部是 `observedAt===0`（未知、零通知）——
**两条路径口径不一致**。

## 我没有直接改，理由

改 `observedAt = 0` 技术上只有一行，但它会连带改变玩家可见行为：
`fresh` 数组只收 `observedAt>0` 的条目，改成 0 意味着这些定义**永远不弹达成通知**。
而"到底该不该弹"是玩法口径，不是可靠性修复。

两个口径，后果完全不同：

| 口径 | 结果 | 代价 |
| --- | --- | --- |
| **A 无来源 → `0` + 零通知** | 与「旧日期留未知」「首次采用」路径一致，不伪造时间 | 1128 条定义达成后玩家看不到提示，可能以为没解锁 |
| **B 无来源 → 当前时间 + 通知**（现状） | 玩家有反馈 | 日期是挂钟，不是首次达成时间；跨设备/换档会给出不同「首次」 |

我倾向 A，但它需要作者一句话确认：**「没有可靠首次来源的成就，允许只显示已达成、不弹达成提示、日期显示未知」**。
在这句话之前不改，避免我替玩家决定反馈行为。
