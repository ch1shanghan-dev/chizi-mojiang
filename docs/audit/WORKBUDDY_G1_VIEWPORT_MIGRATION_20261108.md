## 二、断点逐值收敛：四档令牌装不下真实代码

用与 E95X 完全相同的扫描口径（`\(\s*max-(height|width)\s*:\s*(\d+)px`）扫全仓
`core/` + `games/` 的 css/html，共 **21 个文件、95 处断点**：

| 轴 | 值（种数） | 出现次数 |
| --- | --- | --- |
| max-height | 330, 340, 350, 400, 430, 440, 450, 480, 500, 520, 560, 599, 600, 620, 640（15） | 63 |
| max-width | 420, 480, 540, 559, 600, 620, 640, 720, 750, 760, 899, 1000, 1199（13） | 32 |

合并去重 **24 种**，与 E95X 的 `BASELINE` 逐项一致。

**关键结论**：E2 定的「四档视口令牌」只有 `tiny-h 330 / short-h 500 / narrow-w 760 / desktop 1365×768`，
覆盖不了中等高度簇（520–640）与中宽簇（899–1199）。所以「统一成四档」或
更早方案里的「统一 420px」都不是可执行目标，硬改会同时改变十几页的触发范围。

### 定案：6 档目标值

| 轴 | 目标 | 令牌 | 来源 |
| --- | --- | --- | --- |
| height | 330 | `vp-tiny` | E2 主值 |
| height | 500 | `vp-wide` | E2 主值 |
| height | **640** | `vp-mid-h` | **新增中间档**（历史 560/599/600/620/640 归并） |
| width | 760 | `vp-narrow` | E2 主值 |
| width | **1000** | `vp-mid-w` | **新增中间档**（历史 899/1000 归并） |
| width | **1200** | `vp-wide-w` | **新增宽屏档**（历史 1199 归并） |

`core/csh_viewport.js` 升 **v2**，新增冻结的 `TARGETS` / `MIGRATIONS` 与
`migrationOf(value, axis)`：返回 `{from, to, axis, token, direction, risk, newTier}`，
`direction`（expand / shrink / same）与 `risk` 由 `from→to` **机械推导**，不手写第二份事实。
分类 `TOKENS` 与四档 `PROFILES` 一个值都没动。

### 风险账（反例自动算，不是估的）

| 类别 | 出现次数 | 含义 |
| --- | ---: | --- |
| same（映射到自身） | 27 | 零风险：330 / 500 / 640(height)、760 / 1000(width)，只需换成令牌不改触发范围 |
| expand | 59 | **高风险**：`max-*` 改大 = 更多屏幕命中该规则，必须逐页比截图 |
| shrink | 9 | **高风险**：改小 = 原屏幕失去该规则，最容易漏视觉回退 |
| 合计高风险 | **68 / 95** | 涉及 20 个文件 |

最高频单项：`height:430→500` **21 处**（主要在 `core/csh_achievement_badges.css`、
`csh_collection.css`、`csh_duel_tables.css`、`csh_layout.css`），一个值决定 21 处，
是下轮收益最大也最需要截图验证的一刀。其次 `width:600→760` 7 处、`width:899→1000` 5 处。

完整逐页清单（每个文件每处 from→to / direction / risk）由反例 `--out` 输出 JSON，
是下轮施工的唯一依据，不靠记忆或方案文字。

## 五、下轮施工顺序（本轮未执行，只定案）

2. **再做 `height:430→500`（21 处）**：单点收益最大，但必须按 §4.4 逐页比
