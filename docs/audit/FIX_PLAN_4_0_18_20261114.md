## 1. 玩家可接受性准则（贯穿全部批次，替代原第 3 问）

作者原话「一定要功能是玩家可以接受的」——按以下准则执行，**实现细节由开发决定，不再向作者提技术选择题**：

| 准则 | 玩家语言 | 验收方式 |
|---|---|---|
| 找得到 | 任何屏幕尺寸下，名录和「相处/记忆/档案」都看得见、点得到，不能藏进一个要猜的按钮，也不能因为屏幕矮就整个消失 | 真实页面走一遍玩家任务：换一个妖灵、切到「记忆」、切回「相处」 |
| 看得全 | 名录能滚到最后一位、详情能滚到最后一项，不出现半截文字、不被悬浮按钮盖住 | 滚到底后末项完整可见；页签与内容矩形零重叠 |
| 不误伤 | 点「立即更新」就是更新，不拿「请等本局结束」糊弄；但更新过程中玩家必须清楚知道正在发生什么，失败有明确恢复入口 | 进度文案覆盖核对→下载→写入→重启；失败保留凭据可重试 |
| 不亏钱 | 局中重启变常见后，带入/补码/钱包凭据必须能完整恢复 | 局中重启回归：重新进桌筹码与补码次数与重启前一致 |
| 不白屏 | 任何图片缺失都自动回退到现有显示，不出现破图/空白头像 | 缺图注入测试 |

> 具体怎么实现（flex 还是 grid、页签常显还是可折叠、名录窄屏怎么排）属于开发选型，按上表验收即可，**不再列为待拍板项**。

## 2. 三条反馈 → 根因与证据（真值沿用，两处按作者指令更新）

### 2.1 「目录下滑卡住」= **图鉴名录**（作者已确认）→ 真 BUG，稳定复现

**根因**：`games/codex.html:83-84`

```css
.rolodexwrap{flex:0 0 196px;min-height:0}
.rolodex{height:100%;overflow-y:auto;...}
```

`.rolodexwrap`（`:467`）里还有 `.roster-search`（`:434-435`，`min-height:44px` + `padding-bottom:8px` = **52px**）与 `.roster-empty` 两个兄弟节点。`.rolodex{height:100%}` 取满整个 wrap 高度，再叠加搜索框 52px → 名录底部被顶出容器，**最后一项永远滚不到**。

**CDP 真值**（`temp/repro-scroll2-1114.json`，注入 50 位名录、滚到底）：

| 视口 | wrap.bottom | 末项 bottom | 溢出 | 视口内可达 |
|---|---|---|---|---|
| 1365×768 | 760 | 812 | **+52** | ❌ |
| 1080×500 | 492 | 544 | **+52** | ❌ |
| 915×412（点开名录） | 404 | 456 | **+52** | ❌ |
| 640×286（点开名录） | 278 | 330 | **+52** | ❌ |

四档一律 +52px，与搜索框高度吻合 → 根因确证。

**门禁为什么没抓到**：`tools/probe_codex_content_host.mjs:42` 的 `selectedVisible()` 只验证 `.gitem.on`（当前选中项），从不验证**末项**；`probe_codex_hierarchy_20261108.mjs` 只测搜索过滤。属**门禁假绿**。

**同类扫描**：全库只有 `codex.html` 是 `height:100%` + `overflow-y:auto` 且带兄弟节点；`career.html:510`、`rank.html:116` 无此问题。

**金鳞市结案**：作者已确认说的是图鉴名录。`games/goldfish.html` 的 `.gridwrap`（`:84`）在 CDP 注入 40 张卡后各视口都能滚到底（`640×286` 下 `max=50`、`lastCardInGrid=True`），**不是缺陷**，仅保留一条末项可达断言做例行巡检。

### 2.2 「三个按钮下滑了还存在」→ 真 BUG（sticky 悬浮重叠）

**根因**：`codex.html:445` `.dnav{position:sticky;top:-1px;z-index:3;background:var(--panel2)}` 位于**滚动容器 `.dinfo`（`:124`，`overflow-y:auto`）内部** → 内容滚动时页签永久悬浮。`.dinfo` 的 `padding-top:14px` 还会漏出被裁切的半行「当前关系…」，正是截图 2 的怪异画面。

**CDP 真值**（1080×500，`.dinfo` 滚 224px）：

| 元素 | 滚前 top | 滚后 top | 位移 |
|---|---|---|---|
| `.dnav` | 119 | 110 | **−9px**（几乎不动） |
| `#bond-brief` | 169 | −63.4 | −232px（被容器顶裁掉） |

`dnavOverlapAff=True`；915×412、640×286 同样成立。

**历史**：`PLAN_4_0_17_20261112.md` P1 已写「图鉴相处/记忆/档案页签压关系摘要」，设计是「页签独立一行 + 下面只留一个滚动容器」，codex 中断前未落地。另 `codex.html:452` `@media(max-height:330px){.dnav{display:none}}` 让极矮屏**完全没有分区切换入口**，而 `probe_codex_sections_20261108.mjs:115` 把这条隐藏写成了「正确行为」——按 §1 准则必须改。

### 2.3 在线更新 → **定案 B：点了就直接更新，玩家等更新过程**

**现状**（`core/csh_debug.js`）：

| 位置 | 现在的行为 |
|---|---|
| `:7975-8019` | 局中只 `prepare()` 不提交，写 `__cshPendingInstall`，显示「更新已下载并核验，**本局结束后自动安装**」 |
| `:7994` | 作者截图里那句提示的出处 |
| `:7888-7927` | `scheduleDeferredInstall()` 轮询「局结束 + 钱包无 pending + 迁移无未决 + 连续两次稳定 + 再等 4s」才提交 |
| `:8041-8044` | 局外更新完成后若开了新局，改成「**本局结束后自动重启**」并每秒轮询 |
| `:7147` | 扩展商城安装入口局中直接 `toast("请在本局结束后安装扩展")` 拒绝 |
| `:8128-8132` | 弹层重开时再次显示等待文案并禁用「立即更新」 |

**B 的准确语义**（按作者「直接更新等待更新就好了」）：

> 玩家点「立即更新」→ 立刻开始 **核对本机文件 → 下载并逐个 SHA-256 核验 → 备份 → 写入 → 重启**。全程只显示**更新进度**（正在核对 X/Y、正在下载、正在写入、更新完成正在重启），**没有确认弹窗、没有「会中断当前局」提示、没有「等本局结束」**。玩家等待的是更新本身，不是等一局打完。局内、局外、商城安装三条入口行为一致。

**B 必须守的红线**（这些不是选择题，是玩家不亏钱/不白屏的底线）：
- 下载按更新目录 SHA-256 逐文件核验，事务 `prepare → commit → recover` 不降级；
- **正在落盘的存档写完才替换文件**（不是「等本局结束」，是「等这一次写入完成」）；
- 一次提交、一次重启，失败回滚，断电可恢复，`writes:false` 与默认离线不变；
- 局中重启会中断当前对局，因此**上线前必须补一条资金回归**：带入 / 补码 / 钱包扣款编号在重启后能恢复（现有 `CURRENT_WORK.md` 记的「德州补码以钱包扣款编号 + 牌桌快照共同确认」链路要实测覆盖局中重启场景）。

`core/csh_svggen.js:321` 的 `avatar()` 生成的是「圆底 + 按 seed/persona 的几何纹样 + `<text>` 姓氏首字」；`core/csh_world.js:2066` 的世界名册头像同样委托程序化生成器，**名册里没有任何图片字段**。座位尺寸只有 `clamp(24px,3.2vh,38px)`（`texas.html:285`）、斗地主 24–36px，属小曝光头像。

### 3.2 这确实是被划掉的旧待办

- `CURRENT_WORK.md:75`（2026-11-10「世界 / 牌桌可见性」）原文：
  > 方案设想的「**牌桌 AI 头像** / 讨伐统计头像」实测**不存在**：牌桌座位是程序化 `CRD.avatar()`、讨伐录用 BOSS 立绘、世界故事卡是文字首字 —— **不硬造展示点**。
  
  即：当初为了把妖灵装扮接到更多展示点，发现牌桌座位根本没有「人物图」这个载体，于是把这项**从待办里划掉**，选择只在对局助战立绘和金鳞市卡面接装扮。
- `docs/art-direction.md:188`（§5.2）写过「**局内头像显示尺寸小 ⇒ 中等规格**」的资产规格决策，但同节状态是「**待作者提供素材，暂不实施**」，从未落地。
- `UI_ART_SFX_PLAN_20261110.md` 的 B1（桌布/桌边/牌背/筹码/底池/结算纹理）与 B2（面板/按钮/24 图标）**都没有头像条目** —— 美术批次也漏了这里。

**结论**：作者记得没错，这是历史遗留。当年「不硬造展示点」是合理的工程判断（当时没有对应图片），但如今**资产已经够了**（见 3.3），不必再等素材。

### 3.3 关键：同桌本来就分两层，两层都有真实人物图

`core/csh_world.js:321` 注释：

> **名册 = 武将 + 妖灵两层**（真源分别 `character/index.js` 与 `csh_bossdata.js`）

`:239-241` 又写明：妖灵主键 `csh_boss_minion_*` 与武将 `csh_*` 前缀隔离、不可能撞 id；**三款牌桌通过 `shell-seat → CSH.world.seat()` 自动能抽到妖灵同桌，无需改任何游戏页**。

| 同桌类型 | id 特征 | 现成图片 | 覆盖 |
