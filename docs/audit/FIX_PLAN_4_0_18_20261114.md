## 1. 玩家可接受性准则（贯穿全部批次，替代原第 3 问）

作者原话「一定要功能是玩家可以接受的」——按以下准则执行，**实现细节由开发决定，不再向作者提技术选择题**：

| 准则 | 玩家语言 | 验收方式 |
|---|---|---|
| 找得到 | 任何屏幕尺寸下，名录和「相处/记忆/档案」都看得见、点得到，不能藏进一个要猜的按钮，也不能因为屏幕矮就整个消失 | 真实页面走一遍玩家任务：换一个妖灵、切到「记忆」、切回「相处」 |
| 看得全 | 名录能滚到最后一位、详情能滚到最后一项，不出现半截文字、不被悬浮按钮盖住 | 滚到底后末项完整可见；页签与内容矩形零重叠 |
| 不误伤 | 点「立即更新」就是更新，不拿「请等本局结束」糊弄；但更新过程中玩家必须清楚知道正在发生什么，失败有明确恢复入口 | 进度文案覆盖核对→下载→写入→重启；失败保留凭据可重试 |
| 不亏钱 | 局中重启变常见后，带入/补码/钱包凭据必须能完整恢复 | 局中重启回归：重新进桌筹码与补码次数与重启前一致 |
| 不白屏 | 任何图片缺失都自动回退到现有显示，不出现破图/空白头像 | 缺图注入测试 |

> 具体怎么实现（flex 还是 grid、页签常显还是可折叠、名录窄屏怎么排）属于开发选型，按上表验收即可，**不再列为待拍板项**。

### 2.1 「目录下滑卡住」= **图鉴名录**（作者已确认）→ 真 BUG，稳定复现

**根因**：`games/codex.html:83-84`

```css
.rolodexwrap{flex:0 0 196px;min-height:0}
.rolodex{height:100%;overflow-y:auto;...}
```

`.rolodexwrap`（`:467`）里还有 `.roster-search`（`:434-435`，`min-height:44px` + `padding-bottom:8px` = **52px**）与 `.roster-empty` 两个兄弟节点。`.rolodex{height:100%}` 取满整个 wrap 高度，再叠加搜索框 52px → 名录底部被顶出容器，**最后一项永远滚不到**。

|---|---|---|---|

| `#bond-brief` | 169 | −63.4 | −232px（被容器顶裁掉） |

### 2.3 在线更新 → **定案 B：点了就直接更新，玩家等更新过程**

**现状**（`core/csh_debug.js`）：

| 位置 | 现在的行为 |
|---|---|
| `:7975-8019` | 局中只 `prepare()` 不提交，写 `__cshPendingInstall`，显示「更新已下载并核验，**本局结束后自动安装**」 |
| `:7994` | 作者截图里那句提示的出处 |
| `:7888-7927` | `scheduleDeferredInstall()` 轮询「局结束 + 钱包无 pending + 迁移无未决 + 连续两次稳定 + 再等 4s」才提交 |
| `:8041-8044` | 局外更新完成后若开了新局，改成「**本局结束后自动重启**」并每秒轮询 |
| `:7147` | 扩展商城安装入口局中直接 `toast("请在本局结束后安装扩展")` 拒绝 |
| `:8128-8132` | 弹层重开时再次显示等待文案并禁用「立即更新」 |

**B 的准确语义**（按作者「直接更新等待更新就好了」）：

> 玩家点「立即更新」→ 立刻开始 **核对本机文件 → 下载并逐个 SHA-256 核验 → 备份 → 写入 → 重启**。全程只显示**更新进度**（正在核对 X/Y、正在下载、正在写入、更新完成正在重启），**没有确认弹窗、没有「会中断当前局」提示、没有「等本局结束」**。玩家等待的是更新本身，不是等一局打完。局内、局外、商城安装三条入口行为一致。

**B 必须守的红线**（这些不是选择题，是玩家不亏钱/不白屏的底线）：
- 下载按更新目录 SHA-256 逐文件核验，事务 `prepare → commit → recover` 不降级；
- **正在落盘的存档写完才替换文件**（不是「等本局结束」，是「等这一次写入完成」）；
- 一次提交、一次重启，失败回滚，断电可恢复，`writes:false` 与默认离线不变；
- 局中重启会中断当前对局，因此**上线前必须补一条资金回归**：带入 / 补码 / 钱包扣款编号在重启后能恢复（现有 `CURRENT_WORK.md` 记的「德州补码以钱包扣款编号 + 牌桌快照共同确认」链路要实测覆盖局中重启场景）。

## 5. 历史遗留逐项详细说明（回应「什么情况」）

> 下列都不是「忘了做」，各有明确原因。每条按「是什么 / 当初为什么没做 / 玩家现在遇到什么 / 要补需要什么」写清。

**5.1 更新面板滚动与操作分区**（`PLAN_4_0_17` 实施顺序 2，P1）
- **是什么**：更新面板里线路列表、进度条、错误详情各自有滚动区，标题和底部按钮没有固定；`csh_debug.js:1816-1825` 内容区独立滚动、`:2197` 错误块 `max-height:190px` 又单独滚。
- **为什么没做**：codex 中断前实施顺序 1（升版/纲手/皮肤/互动）做完就停了，顺序 2 标着「按上面的顺序处理」。
- **玩家遇到什么**：线路多时要一处一处滚，标题滚没影、状态/按钮对比不足，容易以为卡住或点错。
- **要补什么**：标题 + 底部主操作固定，中段**单一**滚动区；线路可完整滚到首末；一次提交一次重启、断电恢复实测。无新增存档键。

**5.2 图鉴页签 / 金鳞市交易条 / 浅深文字 / 数值单位**（实施顺序 4，P1）
- **是什么**：页签问题见 §2.2；金鳞市要把手数/报价/操作合成紧凑底栏，现价与持仓为主，次级资料折叠；浅纸底/深底两套正文对比；调试卡片「亿」等单位与数字被拆行。
