## 2. 三条反馈 → 根因与证据

### 2.1 「目录下滑卡住，不能完全显示」→ **真 BUG，稳定复现**

**根因**：`games/codex.html:83-84` 把左栏写成

```css
.rolodexwrap{flex:0 0 196px;min-height:0}
.rolodex{height:100%;overflow-y:auto;...}
```

而 `:467` 的 DOM 里，`.rolodexwrap` 有**三个**子节点：`.roster-search`（`:434-435`，`min-height:44px` + `padding-bottom:8px` = **52px**）、`.rolodex`、`.roster-empty`。`.rolodex{height:100%}` 直接取满整个 wrap 高度，再叠加兄弟搜索框的 52px → 名录底部被顶出容器 52px，最后一项永远滚不到可视区。

**CDP 真值**（`repro-scroll2-1114.json`，注入 50 位名录、滚到底后）：

| 视口 | wrap.bottom | 最后一项 bottom | 溢出 | 相对视口可达 |
|---|---|---|---|---|
| 1365×768 | 760 | 812 | **+52** | ❌ |
| 1080×500 | 492 | 544 | **+52** | ❌ |
| 915×412（点开名录） | 404 | 456 | **+52** | ❌ |
| 640×286（点开名录） | 278 | 330 | **+52** | ❌ |

四档一律 +52px，与搜索框高度完全吻合 → 根因确证。

**为什么门禁没抓到**：`tools/probe_codex_content_host.mjs:42` 的 `selectedVisible()` 只验证 `.gitem.on`（当前选中项）在名录可视区内；`tools/probe_codex_hierarchy_20261108.mjs` 只验证搜索过滤逻辑。两者都不检查**末项**。

**同类扫描**：全库只有 `codex.html` 用 `height:100%` + `overflow-y:auto` 且带兄弟节点；`career.html:510`（`max-height:100%`）、`rank.html:116`（`flex:1;min-height:0`）无此问题。

**关于「金鳞市」这个称呼**：两张截图都是**妖灵图鉴**，且 `codex.html:516` 空态文案写着「五十位妖灵在金鳞市挂牌」。`games/goldfish.html` 的卡片列表 `.gridwrap`（`:84`）在 CDP 注入 40 张卡后各视口均可滚到底（`640×286` 下 `max=50`，`lastCardInGrid=True`），未复现同款溢出。**不擅自替作者判定**是口误还是另一处真机症状 —— 修复批次里同时给金鳞市加一条末项可达断言，真机复核。

### 2.2 「相处/记忆/档案下滑了还存在」→ **真 BUG（sticky 悬浮重叠），`PLAN_4_0_17` 已知未修**

**根因**：`games/codex.html:445`

```css
.dnav{display:flex;gap:6px;flex:none;position:sticky;top:-1px;z-index:3;background:var(--panel2)}
```

`.dnav` 是**滚动容器 `.dinfo`（`:124`，`overflow-y:auto`）内部的子元素**，`position:sticky` 让它在内容滚动时永久悬浮在顶部 —— 这就是作者说的「不会消失，而是下滑了还存在」。同时 `.dinfo` 有 `padding:14px 16px 12px`，sticky 元素只覆盖自身矩形，上方 padding 区会漏出被裁切的半行「当前关系…」（截图 2 页签上方那半行文字）。

**CDP 真值**（1080×500，`.dinfo` 内容滚 224px）：

| 元素 | 滚动前 top | 滚动后 top | 位移 |
|---|---|---|---|
| `.dnav` | 119 | 110 | **−9px**（几乎不动） |
| `#bond-brief` | 169 | −63.4 | −232px（被容器顶裁切） |

`dnavOverlapAff=True`；`915×412`、`640×286` 同样成立。`z-index:3` + 不透明底色使滚上来的内容在页签矩形内被盖住 → 形成「半截文字 + 悬浮按钮」的错位观感。

**这不是新问题**：`docs/audit/PLAN_4_0_17_20261112.md` P1 已写「图鉴相处/记忆/档案页签压关系摘要；`codex.html` 的详情滚动区里有 sticky dnav，关系摘要和页签会占据同一阅读区域」，设计方案是「把页签放在独立的一行，下面只留一个滚动容器」—— codex 中断前**未落地**（实施顺序 4 仍标未完成）。

**附带的第二个缺陷**：`codex.html:452` `@media(max-height:330px){.dnav{display:none}}` 让极矮屏**完全没有分区切换入口**（记忆/档案不可达）；而 `tools/probe_codex_sections_20261108.mjs:115` 把这条隐藏规则当成正确行为写进了断言，属于把缺陷锁成契约，修复时必须同步改判据。

### 2.3 「在线更新仍然要等游戏结束」→ **产品策略冲突，`PLAN_4_0_17` P0 已设计未落地**

**现状代码**（`core/csh_debug.js`）：

| 位置 | 行为 |
|---|---|
| `:7975-8019` | `inGame = _status.gameStarted && !_status.over` 为真时只 `task.tx.prepare()`（下载+备份+journal），写 `__cshPendingInstall`，提示「**更新已下载并核验，本局结束后自动安装**」，然后 `scheduleDeferredInstall()` |
| `:7994` | 作者看到的原话就在这里 |
| `:7888-7927` | `scheduleDeferredInstall()` 轮询 `settledNow()`：局结束 + 钱包无 pending + 迁移无未决 + 连续两次稳定 + 再等 4s 才 `commit` + `game.reload()` |
| `:8041-8044` | 即便局外更新完成，若期间开了新局，改成「**本局结束后自动重启**」并每秒轮询等待 |
| `:7147` | 扩展商城 `installEntry()` 局中直接 `toast("请在本局结束后安装扩展…")` 拒绝 |
| `:8128-8132` | 弹层重开时再次显示「本局结束后自动安装」并禁用「立即更新」 |

**结论**：不是 bug，是**上一版按「避免重启打断结算」设计的有意延迟**，与作者现在要的「随时随地能更新好」直接冲突。`PLAN_4_0_17` P0 的设计原文已写明正确方向：

> 检查与下载任何时候可用。玩家点「现在更新并重启」可主动提交，局中明确提示当前局可能中断；也可选择「先下载」，到玩家选择重启时再提交。**正在落盘时等待存档写完，不以整场结束作为前置条件。** 无差异显示文件完整，无需重启。保持摘要、原文件备份、断电恢复和旧档。

codex 只做了事务层 `prepare/commit/recover`（`tools/probe_update_deferred_20261105.mjs` 等 12 个探针覆盖），**UI 策略没改**。

**需作者拍板的一点**：局中立即更新必然重启并中断当前对局。方案给两个选项（§4.3 A/B），不擅自决定。

## 4. 修复方案（**全部待批准，本轮未实现**）

### 4.1 批次 A · 名录末项可达（低风险，建议先做）

- `games/codex.html`：`.rolodexwrap` 改 `display:flex;flex-direction:column`；`.rolodex` 去掉 `height:100%`，改 `flex:1 1 auto;min-height:0`；`.roster-search` 与 `.roster-empty` 保持 `flex:none`。窄屏 `.codex-roster-open .rolodexwrap` 同步继承。
- **不动**搜索框、名录渲染、排序、`#rolodex .gitem[hidden]`。
- **验收**：新增浏览器断言「四视口 × 50 位名录 × 滚到底 → 最后一项 `bottom ≤ rolodexwrap.bottom+1` 且 `≤ innerHeight+1`」；改前基线必须判红（当前 +52px）。同步补 `selectedVisible()` 现有断言不退化。
- **风险**：极低，只改布局盒模型。

### 4.2 批次 B · 页签与滚动分层（中风险）

- 按 `PLAN_4_0_17` 实施顺序 4 的原设计：把 `.dinfo` 改成**不滚动的 flex 列外壳**，内部新增 `.dinfo-scroll{flex:1 1 auto;min-height:0;overflow-y:auto}` 承载 `#codex-relationship` + 三个 `<details>`；`.dnav` 移出滚动流，`position:static`（去掉 `top:-1px` / `z-index:3`），独占一行 `flex:none`。
- 极矮屏不再 `display:none`，改为压缩一行小按钮（保留分区可达）；**同步修改** `probe_codex_sections_20261108.mjs:115` 的断言与 `probe_codex_sections` 的 DOM 选择器假设。
- `applySection()` 按 `data-section` 切 `hidden` 的逻辑保持不变，但需确认它的滚动复位目标从 `.dinfo` 改为 `.dinfo-scroll`。
- **验收**：① 滚动 224px 后 `.dnav` 与 `#bond-brief`/`.affbox` 矩形**零重叠**；② 页签不再随内容移动也不盖住内容；③ 最后一项互动/赠礼按钮滚到底完整可见；④ 三档横屏 + 1365×768 截图目视；⑤ `E95BB` 62/0、`probe_codex_content_host`、`probe_codex_hierarchy` 不退化；⑥ 改前基线判红。

### 4.3 批次 C · 在线更新改为「随时更新」（**高风险，需作者先拍板**）

**共同红线**（无论选 A/B）：下载按目录 SHA-256 逐文件核验、事务 `prepare → commit → recover` 不降级、**正在落盘的存档写完才替换文件**、一次提交一次重启、失败回滚、断电可恢复、`writes:false` 与默认离线不变。事务层 12 个探针全部保留。

| 选项 | 行为 | 代价 |
|---|---|---|
| **A（推荐）** | 局中照样立即 `commit` + 重启，但提交前弹一次明确确认「当前对局会中断，是否继续？」；另保留次要入口「先下载，稍后手动装」 | 多一次点击，但不会误中断对局 |
| **B（作者字面要求）** | 点「立即更新」即直接装好并重启，局中不给任何提示 | 完全无等待，但会静默中断当前局 |

**改动点**：
- `csh_debug.js:7975-8019` 去掉 `if(needed.length && inGame)` 的延迟分支，统一走 `task.tx.apply(...)`（或 `prepare` 后立即 `commit`，保留事务原子性）。
- `:8041-8044` 去掉「本局结束后自动重启」轮询，改为提交成功后直接 `game.reload()`。
- `:7147` 商城安装入口同步放宽（否则从扩展商城装仍被挡）。
- `:8128-8132` 与 `:7994` 文案改为「更新完成，正在重启…」/「当前对局将中断，确认继续？」。
- `:7888 scheduleDeferredInstall()`、`__cshPendingInstall`、`__cshCancelPending`：**保留事务能力**（断电恢复仍需要），但 UI 不再默认进入等待；`probe_update_cancel_pending_20261105.mjs` 的注释与围绕「本局结束后自动安装」写的判据需同步更新。
- **验收**：新增探针覆盖「局中 `_status.gameStarted=true && over=false` 时点立即更新 → 事务走到 committed、版本写回、reload 被调用、无 `本局结束后` 文案」；改前基线判红；另跑 `check_update_suite.mjs` 全套、`probe_update_transaction.mjs`、断电恢复、拒写回滚。
