# 妖灵图鉴装扮入口首批

日期：2026-11-04。本轮一次，不循环。只负责图鉴装扮入口及可扩外观注册；4.0.14，不提交推送，不生成/替换其他角色立绘。

## 已实装

- `games/codex.html`人物标题内加入低频“装扮”入口。横屏预览为左主图、右可用形象和操作，支持原生返回/Escape/Tab焦点保护；切换人物和关闭页面销毁旧弹层，旧处理器不能改新人物。
- 当前正式内容只显示原有“经典形象”，一条简短后续说明；没有假皮肤、未提供素材卡片或虚构购买入口。所有妖灵的经典图仍取现有图鉴真源。
- 新`core/csh_spirit_skins.js`提供稳定ID的register/list/resolve/select。以canonical妖灵ID加skinID配置多套本地图片，可分别给立绘、头像和封面；助战逻辑别名可归一到同一妖灵。当前生产注册表为空，未来作者提供文件后录入本地配置。
- 选择只局部更新图鉴主图和名录缩略图，不重建关系控件，不修改好感、奖励、次数或战斗对象。classic恢复、未知/撤回皮肤和图片失效回经典；经典本身失效仍留姓名占位。
- 本机外观KEY为`csh_spirit_skin_v1`，结构`{v:1,selected:{[canonicalId]:skinId}}`。iframe明确使用宿主localStorage，与导入导出真源一致；宿主读取失败不另开一份页面偏好。保存严格读回确认；读错不清空旧偏好，未确认时保留当前画面供重试。
- 仅本地图片路径白名单，不接受远程URL、上级路径、SVG或原型键。外观状态只存稳定ID，不把文件路径写进玩家选择存档。

## 作者素材接入

后续由作者提供妖灵名、皮肤名、原图、可选头像/封面及裁切意愿；开发时映射稳定skinID与本地资源。数据录入例如：

```js
CSHSpiritSkins.register('csh_boss_minion_eve', [
  {id:'daily',name:'实际素材名称',portrait:'image/spirit-skins/eve/daily.webp'}
]);
```

例子是接入规范，不是已提供或已注册皮肤。无需让作者手写配置或懂内部路径。没有固定每人3套/4套约束；有多少真实素材，就呈现多少实际条目。
