# 取消待安装（2026-11-05）

## 触发

作者口径：「任何时候都应该可以更新」。反过来说，**任何时候也应该可以反悔**。

4.0.16 起，对局中可以先下载并核验、本局结束后自动安装（见 `BACKLOG_IN_GAME_UPDATE_PLAN_20261105.md`）。
但此前后果是单向的：一旦下好，玩家只看到按钮变灰、状态写着「本局结束后自动安装」，
没有办法撤回 —— 想换个版本、腾空间、或者干脆不想现在动文件，都只能等本局结束被换掉。

## 改了什么

**`core/csh_debug.js`**（唯一运行源码改动）：

1. 新增 `window.CSHUpdate.__cshCancelPending()`：
   - 没有待安装 → `{empty:true}`，什么都不做。
   - 取消进行中再次点击 → `{busy:true}`，不并发。
   - 调用 `tx.abortPrepared()`；**只有成功才清 `__cshPendingInstall`**。
   - 失败（例如已经进入提交阶段）→ `{cancelled:false, refused:<原因>}`，**保留待安装凭据**。

   挂在 `window.CSHUpdate` 而不是闭包局部函数：`probe_update_transaction.mjs` 会把
   `startUpdate` 单独抽到 vm 里跑，那里没有外层闭包。

2. 局后自动安装的轮询新增两处检查：
   - 轮询开头：`__cshCancelInFlight` 为真时**推迟**（`setTimeout(tick,1500)` 后重试），不是直接停。
   - 最终提交前：`__cshCancelInFlight` 为真则放弃这一轮。

3. UI 两个入口都给「取消待安装」：
   - 重新打开更新面板时（`applyCatalog`）：状态直接写「已下载并核验 X，本局结束后自动安装；当前文件未改动」，
     「立即更新」置灰，旁边给「取消待安装」。
   - 局中预下载刚完成时（`startUpdate` 内）：同样插入取消按钮。
   - 取消成功 → 按钮移除、「立即更新」恢复可点、状态改为「已取消待安装」。
   - 取消失败 → 按钮恢复可点、状态如实写失败原因，**不谎报已取消**。

4. 建按钮的代码包在 `try/catch` 里：单抽 `startUpdate` 的 vm 探针没有 `document`，
   不能因为建不出按钮就让「已就绪」变成异常。

## 自己抓到的两个错

1. **初版先清凭据再取消** —— 如果此时已进入提交阶段，界面会说「已取消」但文件仍在被换。
   改成「成功才清」，并且在取消进行中让自动安装**推迟**而不是照常提交。
2. **初版在 `startUpdate` 里直接 `document.createElement`** —— 事务探针立刻报
   `document is not defined`，把「已就绪」状态整体打挂。已降级处理。

## 边界与残余

- **提交阶段不能取消**。那时文件正在被替换，中途取消只会留下更糟的中间态；
  拒绝并如实提示，是本轮刻意的取舍。
- 取消失败时**不会**自动回退到「不安装」；本局结束后仍会安装，界面已经说清楚。
- `abortPrepared` 只清 journal，**暂存文件本身**留给下次启动的 `recover`/备份清理处理，
  不在这里做递归删除（避免半删状态）。
- 取消按钮只在「已就绪」之后出现；下载过程中取消仍然走原来的「取消下载」。
- 未做真机触摸验证（按钮在窄屏的位置、手指命中区），归作者的真机验收。
