# 金鳞市 ZIP 更新保全与缺档恢复（2026-10-22）

本轮为 4.0.10 发布后的本地修复；未升版、提交、推送、打包或发布。未读取或写入真实玩家浏览器 profile，测试只使用临时 Chromium profile、合成余额和持仓。既有武将 AI 不在范围内。

## 已确认根因

1. 本机宿主 `noname/game/index.js:3011` 的 ZIP 同名导入会调用 `game.removeExtension(name2, true)`。其 `removeExtension`（同文件 5986 行）逐个删除 `extension_池子魔将*` 配置。`true` 只保留扩展文件，不保留配置。故 `extension_池子魔将_goldfish` 会被删除；直接覆盖磁盘文件不是这条路径。
2. 市场旧版仅在未完成交易时把持仓放入 `csh_wallet.marketPending`，同步成功后清理。配置删除后，已完成交易没有独立持仓真值。过去把缺值和读取异常降级为 `blank()`，使缺档看似零持仓，并可能再次触发体验金。
3. 新增永久 `marketSaved` 后，读取优先级为 pending → saved → 宿主配置 → 已知历史 LS。若只导入 `goldfish`、保留本机钱包，旧 saved 会优先于导入配置。本轮已复现：移除关联写入计划后，专项有 5 项失败，包含导入后可见持仓、重启、原钱包 journal 和故障恢复。
4. 页面曾在刷新失败后继续显示上次快照，却没有独立不可用状态；旧值看似仍可交易。

## 本地修改

- `core/csh_wallet.js:494/547`：已确认同步状态永久保留为 `marketSaved`；检查点仍负责未完成的原子交易。余额和持仓首先同一次钱包写入，宿主配置为异步同步目标。
- `core/csh_market.js:920/943`：严格读取配置，等待 IDB 事务完成；读取失败返回不可用并禁止交易/日结，原数据不改。启动安装即保全仍存在的旧配置。检测到历史市场流水或市场备份却缺少持仓时，暂停自动开户。
- `core/csh_market.js:976`：仅缺档且明确确认时允许使用新市场，零持仓且标记已领体验金；不会重复赠款。已有备份保留。
- `core/csh_migrate.js:1027/1183`：导出/备份取 pending 或 saved 真值；导入和回滚的配置与钱包副本使用同一份持仓。即使文件只有 goldfish，也将原钱包纳入写入计划及恢复 journal，失败恢复原始字节。迁移不携带本机待同步任务；变化后的钱包按原有无签名导入流程采用。
- 交叉审核补修：历史 `numMap` 把空 hold/cost 输出为 null，与严格读取器冲突。新导入始终输出 `{}`；读取器只在副本上把历史合法 hold/cost:null 规范为空对象，数组/字符串等非法形状仍拒读并保留原始存储。补齐零持仓导入、回滚、重启、历史 null 档与非法形状回归。
- `games/goldfish.html:333/348/727`：`Data.unavailable` 独立于旧快照。读取失败保留“上次快照 · 只读”提示并禁用买卖；UI 点击和传输 helper 都检查不可用状态。成功重新读取后恢复入口。

## 恢复边界与未验证

可确定恢复的是：仍存在的宿主配置、已知同键历史 LS、钱包 pending/saved，或玩家明确选择的旧备份。已有旧备份可在行囊检查并回滚；回滚整份备份也会回退其覆盖的其他域，不能把它描述成只恢复股票。

若此前 ZIP 更新已经删掉市场配置，且没有上述副本，本补丁无法凭空还原持仓。流水只作缺档证据，不从余额变化猜测股数、成本或历史价格。如果连历史流水/备份证据也不存在，无法区分曾经丢档与首次安装；本轮未声称能识别所有历史损失。补丁保全也依赖其至少成功运行、写入过一次；存储配额或写入失败会显式报错并保留原配置，不能保证下一次未运行扩展的 ZIP 导入前已完成保全。

浏览器专项运行真实宿主 removeExtension 源码方法，使用测试实现的宿主 saveConfig 后端并等待原生事务完成；没有调用完整 importExtension 解压/文件安装，也没有启动完整无名杀或读取玩家档。未覆盖安卓 WebView、手机布局、跨设备恢复及真实玩家已丢持仓的恢复结果。没有为了验证而导入真实 ZIP 或卸载真实扩展。
