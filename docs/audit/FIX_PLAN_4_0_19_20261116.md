## 1. 问题 1 · 牌桌头像没变成图片（P0）

### 1.1 证据链

1. 截图（德州桌）四个座位仍是圆底 + 单字「神 / 姬 / 兀 / 马」——这是 `CRD.avatar()` 生成的程序化 SVG，不是真人立绘。
2. 接线本身在：`core/csh_cards.js:218` `facePath()`、`:234` `faceHTML()`；四桌五处调用点都在（texas:2705、blackjack:1464、doudizhu:1941、uno:1602）。
3. `facePath()` 武将分支返回 `"../image/" + id + ".jpg|webp"`（`core/csh_cards.js:229`），妖灵分支返回 `"../" + sk.face`（`:225`）。
4. **路径层级错**：牌桌页位于 `games/texas/`、`games/blackjack/`、`games/doudizhu/`、`games/uno/`。浏览器按**文档 URL** 解析图片 src，`../image/` 从 `games/texas/` 出发 → `games/image/`，该目录**不存在**（实测 `ls -d games/image` 无输出；根目录 `image/` 才存在）。正确相对路径应为 `../../image/`。
5. 404 后 `core/csh_cards.js:258-266` 的 `document error` 监听把 `<img>` 换回 `avatar()` SVG——因此**界面看起来完全没接**，且不会抛 JS 报错、不留给日志。

### 1.2 为什么门禁没抓到（假绿）

`tools/probe_table_faces_20261114.mjs` 的 18 条断言全在 VM/静态层：验证 `id → 文件名` 映射、`csh-face-img` CSS 存在、五处调用点源码文本、`skinOf` 跟随逻辑。**没有一条在真实页面里检查 `img.naturalWidth > 0`**。路径错误属于浏览器解析语义，静态字符串断言天然看不见。

### 1.3 修复方案

| 步骤 | 做法 |
|---|---|
| 1 | `facePath()` 不再输出硬编码 `../image/`；改为按当前文档位置计算**根相对路径**：以 `document.baseURI` 为基准向上找到含 `image/` 的目录，或直接统一返回 `../../image/`（四桌都在 `games/<sub>/`，层级一致）。妖灵 `sk.face` 同理加一级。 |
| 2 | 加 `onload` 成功标记（`data-loaded=1`），只在**真实解码成功**时才算接入；`error` 回退逻辑保留但增加 `console.warn` 一次，避免同类假绿再次静默。 |
| 3 | 覆盖 `<base>` 标签与 file:// / http:// 两种宿主形态；`escAttr` 继续防 XSS。 |
| 4 | 新增门禁：真实 Chromium 打开四桌，`document.querySelectorAll('img.csh-face-img')`，断言 `naturalWidth > 0` 且 `data-loaded=1`；同 id 十局图片 URL 不变、妖灵换装后 URL 跟随 `skinOf`。 |

### 1.4 验收 / 风险

- **验收**：四桌每位玩家座位显示真人头肩图；断图率 0；无 JS 报错；24px 小尺寸仍能辨认（真机另测）。
- **风险**：武将立绘是全身图，`object-position:50% 12%` 在部分图上可能裁到胸口以下；施工时用真实四桌截图逐张调 `object-position`，必要时按 id 白名单微调。

## 2. 问题 2 · 好感度徽章位置（P1）

### 2.1 证据链

- `games/goldfish.html:640-648` `renderCardAff()`：`card.querySelector(".face").appendChild(b)` —— 徽章挂在 `.face`（人物图片区）。
- `games/goldfish.html:175` `.affbadge{position:absolute;right:7px;bottom:30px;...}` —— 图片区高度远大于信息区，`bottom:30px` 正好落在人物脸部右下方。
- 截图四张卡（572 / 492 / 522 / 502）心形徽章全部压在脸上，与左上角「持 / 热度」标签相比明显碍眼。

### 2.2 修复方案

- 把 `affbadge` 与 `tipdot`（`games/goldfish.html:650-655`，同一 `.face` 挂载）一起移到**卡片底部信息栏**（价格与涨跌同一行）右端，或图片区**左上角**与「持 / 热度」并排——选其一由开发按实际截图定，标准是不遮脸、不看第二眼也能找到。
- 保留粉色心形与 S 档脉冲动效（玩家已熟悉的识别符号），只换挂载容器与定位。
- 窄卡 / 极矮视口下做溢出保护：数字最多 6 位，超出用「万」缩写，不换行、不挤掉价格。

### 2.3 验收 / 风险

- **验收**：四张卡在 1080×500 / 640×286 下徽章均不覆盖人物面部、不遮挡价格与涨跌幅；`title` 悬浮仍显示「好感 N · 等级」。
- **风险**：移动后可能与「趋势」文字重叠，需浏览器几何实测，不可只看 CSS。

## 3. 问题 3 · 切不回经典形象（P0）

### 3.1 证据链

1. 截图（希里 · 装扮）：列表显示「经典形象 · 已解锁」「城垣 · 10,000 CBY」「暖烛 · 当前使用」「林间 · 10,000 CBY」；下方提示「**装扮保存尚未确认，当前画面未改变，可稍后重试。**」——点了「恢复经典」但画面没变。
2. 提示文字唯一来源：`games/codex.html:1462`，即 `Bridge.call("shell-skin-buy", …)` 返回 `ok=false` 且 `res.reason !== 'poor'` 时的兜底分支。
3. 「恢复经典」接线：`games/codex.html:1467` `restore.onclick = function(){ if (accept("classic")) show(rows[0], true); }` —— 它复用了购买函数 `accept()`，走 `shell-skin-buy` 桥。
4. 宿主侧：`core/csh_shell.js:2163` → `unlockSkin()`（`:2659`）；classic 分支调 `S.prepareSelect(id,'classic',current)` 再 `W.commitSpiritSkins(selected, 0, "装扮切换")`（`:2664-2667`）。
5. 钱包侧：`core/csh_wallet.js:840` → `commitCheckpoint()`（`:806`），失败分支包括 `saveBlocked()`、参数无效、`validateSpiritSkins(state)` 失败、`validateCheckpointLedger` 异常、**存档写入失败**（`:820`）等；`unlockSkin` catch 还会返回 `reason:'error'`。
6. 现有门禁 `tools/probe_spirit_skins_catalog_20261109.mjs:116` 只验**模块层** `S.select(...,'classic') === true`，完全没走桥与钱包检查点——所以「模块能切」≠「玩家点得动」。

### 3.2 修复方案

| 步骤 | 做法 |
|---|---|
| 1 | **先取真因，不改代码**：在宿主控制台复现一次点「恢复经典」，把 `Bridge.call` 的 `res.reason` 与 `lib.cshWallet.spiritSkinsSaved()` 读出来，落到方案附录。禁止在不知道 reason 的情况下猜着改。 |
| 2 | 按 reason 分流修：`saveBlocked` → 检查是哪个未决检查点挡住（近期在线更新 B 的局中重启、迁移 pending），给玩家明确指引；`state 无效` → 修 `prepareSelect` 与 `validateSpiritSkins` 的结构契约；`存档写入失败` → 查 `persistWallet` 与宿主 save 通道。 |
| 3 | **UI 分叉**：「恢复经典 / 使用已解锁装扮」不该走 `shell-skin-buy`（购买语义），应走独立的 `shell-skin-select` 桥或让 `unlockSkin` 对 classic / 已解锁分支走无扣款专用路径；失败提示必须显示 `res.reason` 的可读映射，不再一律「尚未确认」。 |
| 4 | 新增门禁：VM 模拟宿主 `commitSpiritSkins` 成功 / `saveBlocked` / 写入失败三态，断言「恢复经典 → 钱包 state 无 selected[id] → `skinOf` 回经典」以及失败时提示不误导。 |

### 3.3 验收 / 风险

- **验收**：任意已解锁装扮（含截图中的「暖烛」）点「恢复经典」→ 余额不变、画面立刻回经典、重开页面仍经典；失败时给出具体原因而非笼统提示。
- **风险**：**不亏钱红线**——classic 切换必须 `charge=0`，任何情况下不得扣 1 万 CBY；门禁需把「余额不变」写成硬断言。

## 4. 问题 4 · 斗地主卡面与选牌手感（P1）

### 4.1 卡面花色重复

- **证据**：`games/doudizhu/doudizhu.html:1873-1887` `cardHTML()` 对普通牌输出三个 span：`.r`（左上点数）、`.mid`（中央大花色 `SUITS[suit]`）、`.s`（右下小花色 `SUITS[suit]`）；CSS 在 `:291-294`。中央与右下同一个花色符号并列出现，即作者看到的「重复」。
- **方案（推荐）**：删掉 `.s`，保留「左上点数 + 中央大花色」的简洁卡面；同时把 `.r` 旁补一个**小花色**（标准扑克的左上「2♥」角标），使点数与花色归属一眼可辨。若作者偏好标准扑克，则改为「左上 / 右下各一组旋转的『点数+花色』角标 + 中央大花色缩小」，但那会多一处花色，需另做 A/B 截图确认。
- **验收**：20 张随机手牌截图无同花色双标；红黑着色正确（♥♦ 红、♠♣ 黑）；`card.rank/suit` 数据与 DOM 一致，出牌判定不受影响。

### 4.2 选牌手感对齐欢乐斗地主

- **现状**：`games/doudizhu/doudizhu.html:2458` `toggleCardAt(x)` 按坐标算索引后 **toggle**（点一次反选一次）；`:2481-2499` 用 `pointerdown`（非触屏）与 `click`（触屏）双通道。没有「按住扫过多张」的批量通道，也没有「全选 / 取消」快捷。
- **欢乐斗地主的关键手感**（对齐目标）：
  1. **单击**：未选 → 选中，已选 → 取消（保留现状）。
  2. **按住拖动扫选**：`pointerdown` 落在未选牌 → 目标态 = 全选；落在已选牌 → 目标态 = 全取消；`pointermove` 按同一坐标索引算法连续把路过的牌**设为目标态**（不是逐张 toggle，否则来回横扫会反复翻转）。这正是一次能选很多牌的核心。
  3. **阈值**：水平位移 > 6px 才进入扫选，避免单击被误判成拖动；`pointerup / pointercancel / blur` 收尾，触屏同样走 pointer events（现触屏只走 click，无扫选）。
  4. **即时反馈**：扫过的牌抬起 + 描边，`#sel-text` 实时更新；目标态切换只在按下那一刻决定，扫选途中不翻转。
  5. **快捷**：保留「提示」「不出」「托管」，新增「全选本手」「清空选择」两个按钮（44px 触控），与扫选互补。
- **不碰**：牌型判定 `classify()`、出牌合法性、托管策略、发牌与结算——只改输入层与视觉层。
- **验收**：真实 Chromium + 触屏模拟：一次拖动选中 8 张以上；来回横扫不出现反复翻转；单击仍可精确取消一张；非法组合提示不变；四档视口 44px 达标。
