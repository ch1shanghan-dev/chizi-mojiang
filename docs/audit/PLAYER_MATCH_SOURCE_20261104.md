# 玩家自然对局统计真源与剩余生涯来源

日期：2026-11-04。4.0.14，本地维护，不提交或推送，不新增定义。本批纠正真实玩家统计，不把新增数据真源说成70条后台采集已完成。

## 发现与复现

`core/csh_winrate.js::capture` 的旧模式桶保存全桌各角色出场；双将本人也逐武将记两条。`core/csh_shell.js::buildStats` 却把全部模式桶求和作为生涯本人场次、胜负、击杀、武将数量。旧 `me.chars` 是本人角色出场，仍会重复双将，也没有本人击杀或逐模式总账，不能简单改成求和它。

隔离VM执行改前真实capture和原聚合：本人双将、一个敌人、本人击杀1、敌人击杀3，一次本人胜局得到3场、2胜、1负、击杀5；旧实现发起8次配置保存。反例不是旧档猜测。证据为 `tools/probe_career_source_20261104.mjs` 与D盘 `source-evidence.json`；10/0表示成功证实问题与范围，绝不是业务修复验收。该研究工具显式读取D盘改前备份，不进正式门禁。

## 本次实施

1. `core/csh_match_reward.js` 复用原生 `gameStart` 与既有实际活动判断，在本局开始固定钱包代次；新增只读 `session()`，不给玩家新增入口，不改变奖励、触发或结算规则。
2. `core/csh_winrate.js` 在明确本人布尔终局时采集一次本人事实。沿用本人 `_trueMe`、十常侍归一本体、双将只扩展本人武将集合。击杀只取本人 `stat.kill`，不加队友或敌方；终局结果以原生本人result为准。仅身份、对决、斗地主、国战，保留two/2v2、identity_normal别名。无开始/无真实活动、观战、回放、辅助、联机、跨代次均不计。
3. 根代理提供钱包 `playerMatches/commitPlayerMatch/validatePlayerMatches` 与待保存 `player-match`。累计、原日期和去重凭据严格同写，失败不发布成功。采集失败保留既有行囊恢复意图。个人ID采用 `personal-` 独立命名空间，避免与原生奖励同一个run.id在全局待保存队列互相覆盖；两种包装顺序与同时拒写已验。
4. `core/csh_shell.js` 仅用新个人账本聚合场次/胜负/击杀/模式。旧 `me.chars` 只可补可证明的本人武将集合，不从全桌桶倒推历史。新增 `wrHistoryPartial/wrObservedSince/wrReadFailed` 供根代理的生涯页说明消费。
5. `core/csh_migrate.js` 的清点/摘要/导入差异同样使用新个人账本；旧档没有个人源时场次为null，绝不把双将出场数说成个人场次。钱包新字段校验与迁移保全由根代理实施。旧全桌、阵营、本人角色战绩照常导出保存，未抹除。
6. `games/save.html` 将不可证明旧场次显示“未知 / 历史场次未完整记录”，已接受新局显示“新记录N场”与起算范围。导入预览两端未知不格式化为0；战绩行允许关键说明完整换行，640×286下不再省略关键范围。生涯页对应说明由根代理负责。

旧已领与已保存资格保全，不撤销、不重发；未知历史不补造日期。新累计是有据下界，不能宣传为玩家全部历史。当前个人账本收据达到10000条时明确拒写而不截断去重；长期压缩/容量策略是后续可靠性工作，不是已完成万局无限规模。
