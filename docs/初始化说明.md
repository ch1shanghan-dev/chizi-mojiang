## 4. 启动与加载主线

```text
无名杀加载 extension.js
  ├─ decadeUI-compat.js
  ├─ main/bootstrap.js
  │    ├─ registry → 共享音画/自检 → wallet → world → badge → shell → migrate
  │    ├─ theme / interact / voice / games / 生涯成就 / 池子成就
  │    └─ 注册 debug、winrate 的动态加载器与 arenaReady/F1 接线
  ├─ character/index.js + character/boss.js
  ├─ card/index.js
  └─ skills/index.js → 合并 skills/boss.js

扩展工厂返回 package / config / precontent / content
  → precontent：称号与前缀样式、联机手气卡、手游播报加载器等
  → content：UI 基座、神将补选势力、讨伐记录、市场、好感度、
             池子成就采集、BOSS 模式、兼容注入、语音和演出等
  → arenaReady / 首次入口：加载胜负统计、调试面板
```

这是模块组织图，具体引擎调用顺序应对照 `docs/engine-notes.md` 与宿主运行代码。
几个容易误改的位置：

- `bootstrap.js` 让 registry 先于钱包、壳和游戏目录就绪；不要因整理 import 打乱依赖关系。
- `csh_debug.js` 与 `csh_winrate.js` 是动态加载，不是 content 时点必然存在。
  设置入口通过 `lib.__cshLoadDebug`、`lib.__cshLoadWinrate` 唤起。
- `precontent` 早于 `content`，手游播报先安装加载器与钩子安装器，等待 content 建立 `lib.cshShoushaFx` 后接管。
- 各 ESM 自己显式导入 `lib/game/ui/get/ai/_status`；其他模块的 import 不会替当前模块声明变量。
- `character/boss.js` 走原生 `game.import("character")` 注册，之后隐藏角色包入口；
  `main/bossmode.js` 安装模式配置，不应另造一份角色注册表。

| 池子成就 | `csh_pool_achv.js`：80 条操作型规则；8 个事件白名单，仅身份/斗地主/对决的合格单机局 |
| UI | `csh_uikit.js` 的 toast/confirm 与 `csh_theme.js` 的主题/层级；页内布局走 `csh_layout.css` |
| 演出 | `main/content.js` 的 `lib.cshShoushaFx.MEDIA`：8 条素材；调用方用 `play()` / `durOf()` |
| 语音字幕 | `core/voices.js`；互动/好感台词另在相应 *_lines 文件 |

共享脚本存在两种装载形式：一部分是依赖引擎的 ESM，另一部分是零 import 的 IIFE，
可由主文档副作用 import，也可由 iframe 的经典 `<script>` 加载。
例如 registry、page、sfx、bgm、svggen、自检和成就引擎。不要在后者中随意新增 ESM import。
`window.CSH` 是公共命名空间，挂载子模块时保留已有属性。

## 6. 页面桥、结算与存档

```text
games/*.html
  → CSHPage.transport（请求号、超时、claim/确认/释放）
  → postMessage
  → csh_shell（校验当前 iframe 来源、分派 shell-*、共享 GUARD）
  → wallet / world / market / affection / achievements / migrate
  → ACK 返回页面
```

页面只在成功 ACK 后标记已结算；超时或失败释放认领，允许重试。
宿主 `shell-settle` / `shell-settle-session` 共用会话守卫并回放成功结果。
经济参数从 registry 取，页面不能另算一套回收率。关闭 iframe 前先导航 `about:blank`，
再拆遮罩，以停止后台人机和定时器。未结算离场沿用壳的确认链。

存储不是一个后端：

- 钱包、世界、两套成就及不少页面偏好使用 `localStorage`。
- 胜负统计、讨伐记录、市场等使用 `lib.config` 与 `game.saveConfig`。
- `core/csh_migrate.js` 的 `KEY_DEFS` 按 JSON、字符串、通配族、引擎配置、多键族区分读取/清洗/写回。
- 行囊页 `games/save.html` 经 `shell-mig-*` 操作宿主数据，不假定 PC 与安卓 iframe 存储同源。
- 池子成就领取还核对独立台账 `csh_pool_achv_pay` 和钱包流水；新增字段要连同迁移表与清洗逻辑一起看。

## 7. 开发与界面约定

优先读 `docs/dev-rules.md`；技术推导与边界看 `docs/first-principles.md`。
本次接手需要记住：

1. 对局逻辑、衍生系统和纯展示保持边界；衍生代码异常不得影响正常牌局，各模块按既有联机守卫运行。
2. 技能核对触发时机、成本、状态清理、AI 和技能间联动；译名及 `_info` 是真实功能的一部分。
3. 以视口与真实缩放计算 UI 边界；宿主 body 有缩放，不能照搬 iframe 的 vw/vh 方案。
4. 新浮层、提示与确认框复用 UI 基座；字号、颜色和层级走已有 token。右上角必须为钱包胶囊与关闭按钮让位。
5. 网络失败保留可见、可恢复的路径；关键经济路径不把失败当成功记账。
6. 不因初始化重新启用已废弃的动皮分档；`main/build-flags.js` 当前恒为静态基础版。

## 9. 发布与工具使用边界

- `package.js.files` 决定运行包内容，目录声明递归覆盖子文件；`docs/`、`tools/` 和本次指南不随当前运行包分发。
- `tools/release.js` 会写入 catalog；传版本参数会改部分元数据，**不会自动替你更新 extension.js 的版本**，仍须核对三处。
- `tools/release.js --push` 包含 add/commit/push，不是只读检查。本轮未运行发布工具、提交或推送。
- 当前 workflow 虽生成 zip，但上传资产步骤已移除，仅创建/更新 Release 说明；不能只看文件头旧注释就认为 tag 会自动交付 zip。
- `hooks/pre-commit` 可通过 `git config core.hooksPath hooks` 启用。本次读取该配置未返回值，未修改 Git 设置。
- `tools/backup.js --slim` 可作业务改动前代码备份；默认备份路径以脚本计算为准，其文件头的相对路径说明已有差异。
- `tools/inventory.js` 仍定位旧的 extension.js 内联大表，拆包后的精确统计要先核对工具实现，不能直接信旧工具口径。
- 不把计划里针对旧 Git 状态的 `reset --hard` 建议当作日常初始化命令。
