## 1. 红线（违反即打回）

1. **版本号只有作者能定**：三处（含各自 `intro`）必须一致；不许「顺手 +1」，不许自己发明号。
2. **改前必须备份**：`node tools/backup.js --slim`（用 Electron node 跑，见 §9）。
   备份、临时脚本、探针页、日志**一律留在扩展目录外** —— 安卓端无名杀会把扩展目录里每个文件都当扩展内容导入。
3. **最小修改**：「最小」约束的是**未经要求**的改动；作者要求「做完整」就做完整 ——
   **范围由作者定，AI 不得放大，也不得缩小**。
4. **禁止万能 Hook**：不得改写 `lib.skill.*` / `lib.filter.*` / `game.*` / `get.*` / `_status.*` 等全局对象来修单个技能。
   AI 问题修在技能自身（`ai.result` / `ai.order` / `filter` / `cost` / `content` / `choose*.set("ai")`）。
   只有「引擎行为 / 全局兼容 / 扩展加载机制」才可考虑全局修改，且须先写清：为什么技能级修不了、
   影响面、副作用、回滚方式、验证情况，**未获批准不得实施**。
5. **禁止吞异常**：核心结算不得 `try{...}catch(e){}`；不得「catch 住继续假装已结算」；
   不得「为了不报错」直接取消功能。允许范围仅：音频、CSS 注入、DOM 动画、非关键 UI、旧 API 探测。
6. **禁止无证据乱改**：`Math.random` / `storage` / `syncStorage` 的判定口径见 §2。
7. **禁止伪造验证**：没跑就说「仅静态检查」；不许写「实机测试通过 / 联机测试通过 / AI 已验证」除非真跑过。
8. **改动必须留痕**：报告（技能·位置·问题·修改·未修改·验证）+ 本文 §10 轮次记录。
9. **玩家文案不得出现开发视角**：禁「防刷」「经济修复」「设计意图」「PC」「回收率」「名次/计分制」等内部术语，
   只写「是什么、怎么用」；不加括号补丁（细则见 §5）。
10. **经济守恒**：任何提高胜率/收益的开关，接入前先算期望 —— **期望 > 0 且可无限重复 = 刷钱漏洞**。
    现行解法：斗地主好牌模式 = 练习局不计输赢（精确归零）；`practice` 标记必须在开局快照进 game 对象。
11. **只走一套账**：结算唯一实现是 `csh_wallet`；localStorage 键名（`csh_*`）不得改，只改导出范围。
12. **小游戏铁律**：单文件自包含 / 零外链 / 禁用 `vw·vh` / 三条关闭链路齐全（见 §4）。

## 2. 判定口径（这些地方不轻易下结论）

- **`Math.random()`**：只有「影响确定性的 AI 决策 / 联机同步的游戏规则 / 需要复现的核心状态」值得查；
  动画、粒子、UI 装饰、严格同分 tie-break、规则本身要随机 —— 不动。
- **`storage`**：看到没 `delete` 不等于内存泄漏。先确认生命周期、是否长期存在、是否被 `mark`/`intro` 读取。
- **`syncStorage`**：看到缺 `syncStorage()` 不等于联机 Bug。先确认该数据是否需要远端可见、是否由事件本身同步。
- **Bug 分级**：A 确定性错误（→可直接修）· B 高概率逻辑缺陷（→修但要写证据）·
  C 策略问题（→不许冒充 Bug，只能建议）· D 纯风格（→不与功能修复混批）。
- **AI 策略争议 ≠ Bug**；证据不足时写「不确定」，不硬改。

## 3. 技能与 AI 规范

**先理解再改**：描述 → 触发时机 → `filter` / `cost` / `content` / `mod` / `group` / `subSkill` / AI / storage / 与其他技能的联动。
**代码行为优先于注释**：四者（描述/注释/AI/content）冲突时，先查真实行为再决定改哪边。

**AI 三层结构**（禁止用全局 Hook 实现「高手逻辑」）：
1. **技能自身 AI**：要不要发动 / 给谁 / 选哪张牌 / 什么时机。
2. **通用纯函数**：目标价值、威胁值、击杀价值、资源价值 —— 只提供数据，不替技能做决定。
3. **局势阶段**：生存 / 发育 / 爆发 / 收割 / 保队友 / 留资源 —— 严禁变成全局 Hook。

**逐项检查**：
- **敌我关系**：自己 / 友方 / 敌方 / 中立 / 未定身份，不得靠座位号或编号猜。
- **目标价值**：血量、手牌数量与质量、装备、判定区、防御、濒死、关键技能、是否主要威胁。
- **发动时机**：不是「能发动就发动」——看阶段、后续牌、是否该等更好的目标。
- **发动成本**：弃牌/血量/标记/装备/次数/觉醒/关键手牌/后续 Combo 资源。
- **连锁技**：这次选择会不会影响后面的连锁收益。
- **多目标**：重点查「有没有把敌方纳入正收益」（五谷丰登、让敌摸牌/回血/给装备/给标记类）。
- **信息公平**：禁止读对手手牌内容、暗置牌名、未公开判定、隐藏 storage。
- **随机**：只在规则要求 / 隐藏信息 / 严格同分时用。
- **响应类（杀闪桃无懈）**：不是「有闪就出闪」；要结合当前伤害、后续杀、对手手牌与技能、自己血量与未来资源。

**异步**：新代码优先 `async content`；旧 Generator 确认等价后可迁移。
`addToExpansion` 等：先取事件对象再 await（`const next = player.addToExpansion(card); next.gaintag.add(...); await next;`）。

**技能文本**：官方用语（摸牌/弃置/展示/交给/获得；「当你…时 / 于…后」）；
作者刻意为之的**特色文本只报告不擅改**（批量检查先出只读报告 → 作者确认白名单 → 才可动手；默认只改 error 级）。

## 4. 小游戏与页面规范

**目录真值 = `core/csh_registry.js` 的 `CATALOG`**（`csh_shell` / `csh_games` / 调试面板全从它派生）。
加一款游戏：CATALOG 加一条 + `csh_games.js` 的 `CARDS` 补文案即可，**不改调试面板代码**。
现役 4 款 + 大厅：德州扑克 · 斗地主 · 廿一点 · UNO · 生涯大厅。
（**神弩手 2026-10-03 移除** —— 唯一的实时游戏，与其余四款节奏不合。）

**结算方式**（`settle` 字段）：`chips` 牌桌类（带入制，回收 = 带入 + 净赢×回收率）·
`rank` 名次类（UNO，门票不返还，按击败对手数计奖）· `none` 非游戏（大厅）。
数值唯一来源：registry 的 `UNO_PER_BEAT` / `UNO_CAP_MULT` 等 —— 消费方（wallet/shell）不许自写回收率。

**页面铁律**：自包含单文件（`games/<目录>/<文件>.html`）· 不依赖扩展内其它 JS / 构建工具 / 服务端 ·
**零外部资源**（图片字体音频 CSS JS 全禁，用 DOM+CSS 画）· **禁 `100vw/100vh`**（父页 body 被 `transform:scale`，
用 `%` / `inset:0`）· 禁注册 Service Worker · 存储键统一 `csh_<短名>_` 前缀。

**关闭链路（三条都必须通）**：页内关闭 / Esc（模态优先，父页只兜底）/ 壳关闭。
关闭子页前必须先把 iframe 导航到 `about:blank` 再拆遮罩（否则人机定时器在后台继续跑）。
**页面级浮动「✕关闭」已全部删除**，新增页面不得再加（壳已有入口，且矮横屏会与局内按钮重叠）。

**音效**：唯一实现 `core/csh_sfx.js`（合成，零音频文件）；`RECIPES` 是纯数据，改音效只动数据。
开关每游戏独立 `csh_<game>_sfx`，音量共享 `csh_sfx_volume`；单次 ≤6 层，方波 peak 0.06~0.10。
**配乐** `core/csh_bgm.js`：只在「池子休闲」面板响（切走即停并还原本体音乐）；
游戏页自动起播要求 `csh_bgm_on_<game> === "1"`（玩家显式开过）。

**结算桥（游戏页 ↔ 壳）**：结算幂等标记只在**收到成功 ACK 之后**落位；超时/失败必须释放认领。
重试安全由壳侧 `GUARD` 保证（`shell-settle*` 共用会话守卫并回放上次结果）。
核心经济路径不得吞异常后按名义额记账：失败要 `logError` + 如实记 0。

## 5. UI / 布局规范（2026-10-03 重写）

**信息分层**（新页面按这条设计，别再往顶部堆行）：
> **决策必需**（常驻，最多一行） > **状态**（可收起） > **存档级**（只在结算层 / 大厅 / 开局页）

顶部常驻条 **≤ 1 行**。教训来源：2026-10-03 之前德州页顶部三层
（壳顶带 40px + 街道/筹码/盲注 + 生涯/带入/连签/第几手）在手机横屏 412px 高里吃掉约 22%，
且顶部一排在座 AI 的台词/行动正好发生在这块被吃掉的空间里。

**骨架** `core/csh_layout.css`（五页共用）：
- `.csh-game` = grid `[ topbar | stage | dock ]`；`.csh-stage` = grid `[ HUD? | board | player ]`
  —— 三行几何上不可能重叠（不靠 z-index 补救）。
- `L-SHORT`（横屏 ≤430px）/ `L-TINY`（≤350px）**只压字号与间距，不藏信息**。
- `.csh-topbar` 右侧预留壳悬浮件的空白带（`padding-right: clamp(148px,19vw,186px)`），
  保证任何页面数据都不被悬浮件压住 —— 单点预留，五页通用。

**壳** `core/csh_shell.js`：顶带已删 → 右上角**悬浮控制组**：余额胶囊 + ✕（半透明 .62，
hover/按下 1.0，触摸目标 ≥44px）。余额必须常驻（2026-09-28 作者要求「一个能看池子币的地方」）。
未结算离场走二次确认（「去结算 / 仍要离开」）。

**台词气泡** `core/csh_page.js`：朝牌桌**内侧**画 —— 座位上方放不下就翻到下方（`.csh-quip.below`），
永不进顶部条带；全页 6 秒节流、同一时刻只留一条、锚点查不到就静默不说。

**调试面板**（`core/csh_debug.js`）：令牌只在注入块单点定义（其余 `var()` 引用）· 纯 CSS 优先 ·
可读文字 ≥12px、字号档 ≤3 · 强调色只服务「当前选中 / 主操作」· 视觉改造不得增加操作步数 ·
判定：整图转灰度后层级仍可辨 = 合格。

**玩家文案**：只写「是什么、怎么用」；内部术语一律不进界面 ——
`PC`→`CBY/池子币`、`回收率`→`结算后按比例回账`、`名次/计分制`→`其余游戏按门票计价`；
不写「期望收益为负 / 设计意图 / 防刷」这类机制解释（进代码注释）。

## 7. 经济与统计口径

- **钱包**（`csh_wallet.js`）：全扩展唯一账本；写操作幂等；总上限 `PC_CAP`；
  门票/带入/回收率/名次系数唯一来源 registry；豪赌桌门槛 `买入 ≥ 200,000`。
- **胜负统计**（`csh_winrate.js`）：按 `player.name1 / name2` 记账（双将各记一条）。
  **十常侍特例**：`player.name === "shichangshi"` 时只记本体 —— 它的 `name1/name2` 是当前两名**化身**
  （`scs_bilan` 毕岚 / `scs_zhaozhong` 赵忠…），照 name1/2 记会把一局记成两条；
  历史 `scs_*` 旧账由 `mergeShichangshi()` 一次性折半合并回本体（幂等）。
- **AI 世界**（`csh_world.js`）：97 人名册（`character/index.js` 唯一真值，加武将自动收录）；
  性格/资金/头像按 `stableHash` 派生；资金分层人数按名册规模派生（`tierCountsFor`，97 人 = 8/18/41/30）；
  **仇恨成对**（`grudges[对象键]`）；世界日序用本地日历（与钱包同日界）；事件环 ≤24 条、措辞按事件哈希稳定；
  叙述层一律**只读派生**，不写经济状态。

## 8. 防回归清单（改代码前过一遍）

- 版本三处一致（含 intro）；localStorage 键名不改。
- 新增存储键 → 同步四处：collect / cleanXxx / applyAll / inspect；
  `cleanXxx` 字段集**从主模块抄**，不手写。
- **字符串日期字段**（`dailyTask.day` / `lastSign` / `reliefDate` / `meritDate`）**不得走 clampNum**（`Number("2026-10-03")` = NaN ⇒ 被钳成 0）；
  **世界数值字段**（`lastTick`）不得走 clampStr。
- 新增渲染点必须 `esc()`；键名只从 `charNames()` 取，不用 `characterTitle`（含 HTML）。
- 离线对局（`playOne`）必须与 `settleWin/settleLose` 同口径维护个人战绩；里程碑用专用字段（如 `everTier3`），不借 `retireCount`。
- 手机横屏：真正的紧凑断点是 `max-height` 系（不是宽度）；HUD/浮层必须显式 `z-index`；
  手势期间创建的浮层必须做 `armClose`（松手 click 会把它关掉）。
- toast 必须设同屏上限；`100vw/100vh` 硬失败。
- 技能 ↔ 译文 ↔ 立绘 ↔ 语音 四向一致；资源引用只用扩展内路径；禁止重命名/删除既有资源。
- 拆包/改结构：不改键名、不顺手优化、一批一备份、每批过门禁。
